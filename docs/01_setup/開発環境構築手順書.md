# 開発環境構築手順書_Tauri v2

## 1. 文書目的
本書は、AIニュースマスコットアプリ「ゆうこのニュース日和」の開発に参加するメンバーが、共通の開発環境を構築できるようにするための手順書である。

本書は、従来の **C++ / Qt / Qt Quick / QML** 前提の開発環境構築手順書とは別に、**Tauri v2 + React + TypeScript + Rust** を第一候補構成とした場合の開発環境を整理するものである。

v2では、実際にWindows環境で環境構築を行い、Tauri + React + TypeScript のテストアプリ起動まで確認した流れを反映する。特に、Git導入、Node.js導入、PowerShellのパッケージマネージャ実行ポリシー、Rust導入、Tauriテストアプリ作成の手順を具体化している。

> 補足（現行main基準）  
> 現行リポジトリは **Next.js + pnpm** を正とする。  
> 本書内に `npm` / `Vite` 記述が残る箇所は、履歴情報を除き原則 `pnpm` / `Next.js` へ読み替える。

## 2. 技術構成方針

### 2.1 採用候補構成

```text
Tauri v2
├─ フロントエンド: React + TypeScript
├─ UIビルド: Next.js
├─ アプリ中核処理: Rust
├─ デスクトップアプリ基盤: Tauri
├─ ローカル保存: Markdown / JSON
└─ AI連携: Gemini API + MockProvider
```

### 2.2 C++の扱い
MVP段階ではC++を使用しない方針とする。

ただし、将来的に以下のような理由が出た場合は、C++ sidecarの追加を検討する余地を残す。

- 既存C++資産を利用したい
- 重い処理を独立バイナリ化したい
- QRコード生成、ZIP処理、特殊なHTML解析などをC++で切り出したい
- C++を学習・活用する目的が明確になった

MVPでは、構成の単純さ、軽量性、保守性、AI駆動開発のしやすさを優先し、Tauri標準のRustバックエンドを利用する。

### 2.3 役割分担

| 領域 | 技術 | 主な役割 |
|---|---|---|
| UI層 | React / TypeScript | 画面表示、画面遷移、ゆうこ演出、ユーザー操作 |
| アプリ基盤 | Tauri v2 | WebView表示、Rust連携、デスクトップアプリ化 |
| 中核処理 | Rust | ニュース取得、AI連携、ローカル保存、辞書、友情ランク |
| データ | Markdown / JSON | ニュース、辞書、設定、ユーザー状態 |
| AI | Gemini API / MockProvider | 要約、用語解説、ゆうこの一言生成 |

## 5. Microsoft C++ Build Toolsのインストール

### 5.1 位置づけ
Tauri / RustのWindows開発では、Microsoft C++ Build Toolsが必要となる。

本プロジェクトではC++アプリを直接開発しないが、RustのWindowsビルドやTauri開発環境のために必要となる。

### 5.2 インストールするワークロード
Visual Studio Build Toolsのインストーラーで、以下のワークロードを選択する。

```text
C++ によるデスクトップ開発
```

左側のワークロードでは、基本的にこれだけでよい。

### 5.3 追加チェック不要のもの
Tauri / RustのWindowsビルド目的では、以下は基本的に不要。

- Web 開発ビルド ツール
- Node.js ビルド ツール
- .NET マルチプラットフォーム アプリの UI 開発
- .NET デスクトップ ビルド ツール
- WinUI アプリケーション開発ビルド ツール
- Azure 開発ビルド ツール
- Office / SharePoint ビルド ツール
- データ ストレージとビルド ツールの処理
- Visual Studio 拡張機能の開発
- Linux および Mac 向け C++ 開発ツール

Node.jsはVisual Studio Build Tools経由ではなく、Node.js公式インストーラーで導入する。

### 5.4 必要コンポーネント
右側の詳細で、以下が含まれていることを確認する。

- MSVC v143以降のビルドツール
- Windows 10 / 11 SDK
- C++ CMake tools for Windows
- C++ コア デスクトップ機能

### 5.5 容量を減らす場合
最低限に近づけるなら、以下は外してもよい可能性がある。

- MSVC AddressSanitizer
- vcpkg パッケージ マネージャー
- Windows 用 C++ ATL

ただし、初回は成功優先で、既定のまま進めてもよい。

### 5.6 インストール後の注意
インストール完了後は、PowerShellやGit Bashなどのターミナルを一度閉じて開き直す。

## 6. Gitのインストール

### 6.1 インストール
Git for Windowsをインストールする。

インストール時の基本設定はデフォルトでよい。

### 6.2 既定エディタの選択
Gitインストール中に、既定エディタを選択する画面が出る。

推奨:

```text
Use Visual Studio Code as Git's default editor
```

VS Codeをまだ使わない場合や迷った場合は、以下でもよい。

```text
Use Notepad as Git's default editor
```

Vimは慣れていないメンバーには扱いづらいため、基本的に避ける。

### 6.3 インストール確認
Git BashまたはPowerShellで以下を実行する。

```bash
git --version
```

例:

```text
git version 2.54.0.windows.1
```

### 6.4 初期設定
初回のみ、名前とメールアドレスを設定する。

```bash
git config --global user.name "Your Name"
git config --global user.email "your.email@example.com"
```

設定確認:

```bash
git config --global --list
```

### 6.5 PowerShellでgitが認識されない場合
Git Bashでは動くがPowerShellで動かない場合は、PowerShellを閉じて開き直す。  
それでも認識されない場合は、Gitインストール時のPATH設定を確認する。

## 8. Node.jsのインストール

### 8.1 インストール
Node.js公式サイトから、Windows用の **LTS版** をインストールする。

選択方針:

```text
OS: Windows
Node.js: LTS
Package manager: npm
Architecture: x64
```

ダウンロードは以下を選ぶ。

```text
Windows インストーラー (.msi)
```

Docker版やzip版ではなく、通常の `.msi` インストーラーを利用する。

### 8.2 インストール時の注意
インストール中の選択肢は、基本的にデフォルトでよい。

「Automatically install the necessary tools...」のような追加ツール項目が出た場合、今回はチェックしなくてよい。  
Build ToolsはすでにVisual Studio Build Tools側で導入しているためである。

### 8.3 確認
インストール完了後、PowerShellを閉じて開き直し、以下を確認する。

```powershell
node -v
npm -v
```

例:

```text
v24.15.0
11.12.1
```

### 8.4 npmがPowerShellで実行できない場合
PowerShellで `npm -v` を実行した際、以下のようなエラーが出ることがある。

```text
このシステムではスクリプトの実行が無効になっているため、
C:\Program Files\nodejs\npm.ps1 を読み込むことができません。
```

この場合、PowerShellの実行ポリシーが原因である。

以下を実行する。

```powershell
Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
```

確認が出た場合は `Y` を入力する。  
確認が出ない場合は、そのままでよい。

設定確認:

```powershell
Get-ExecutionPolicy -Scope CurrentUser
```

以下が表示されればよい。

```text
RemoteSigned
```

その後、PowerShellを閉じて開き直し、再度確認する。

```powershell
npm -v
```

### 8.5 cmdで確認する方法
PowerShellでうまくいかない場合、コマンドプロンプトで確認してもよい。

```cmd
npm -v
```

cmdで動けば、npm自体は導入できている。

## 9. Rustのインストール

### 9.1 インストール
Rustはrustup経由でインストールする。

Windows x64環境では、Rust公式サイトから以下を選ぶ。

```text
RUSTUP-INIT.EXE(X64) をダウンロードする
```

32-bitやARM64ではなく、通常のWindows PCではX64を選択する。

### 9.2 rustup-init実行
ダウンロードした `rustup-init.exe` を実行する。

黒い画面で選択肢が表示されたら、基本は標準インストールを選ぶ。

```text
1) Proceed with standard installation
```

そのままEnterで進められる場合もある。

### 9.3 確認
インストール完了後、PowerShellを閉じて開き直し、以下を確認する。

```powershell
rustc --version
cargo --version
```

例:

```text
rustc 1.95.0
cargo 1.95.0
```

### 9.4 Rust Analyzer
VS CodeでRust開発を行う場合は、Rust Analyzer拡張を導入する。

本番プロジェクトを作成する前に、Tauri + React + TypeScript のテストアプリを作成し、環境構築が成功しているか確認する。

cd C:\Users\<ユーザー名>\OneDrive\デスクトップ

## 16. Gemini API設定

### 16.1 基本方針
開発段階では、Gemini API Free Tierを利用する想定とする。

ただし、APIキーはコードに直書きしない。  
React / TypeScript側へAPIキーを渡さず、原則としてRust側で参照する。

### 16.2 APIキーの設定方法
初期候補として、環境変数を利用する。

```bash
setx GEMINI_API_KEY "your-api-key"
```

PowerShellの場合:

```powershell
[Environment]::SetEnvironmentVariable("GEMINI_API_KEY", "your-api-key", "User")
```

設定後、ターミナルやVS Codeを再起動する。

### 16.3 Rust側の参照方針
アプリはRust側で環境変数 `GEMINI_API_KEY` を参照する。

APIキーが存在しない場合は、以下のいずれかの挙動とする。

- MockProviderへ自動切替
- 設定画面で警告表示
- AI機能を一時無効化

MVPでは、MockProviderへ切り替えられることを優先する。

### 16.4 禁止事項
- APIキーをソースコードに直書きしない
- APIキーをGitにコミットしない
- APIキーをReact側へ渡さない
- APIキーをログに出力しない
- APIキーをスクリーンショットや発表資料に写さない
- `.env` をGit管理しない

### 17.1 目的

### 17.2 想定用途

### 19.1 Rust側の責務

### 19.2 Tauri command
React側からRust処理を呼ぶ場合は、Tauri commandを利用する。

例:

```rust
#[tauri::command]
async fn get_recommended_articles() -> Result<Vec<ArticleSummary>, String> {
    // Rust側でニュース一覧を取得する

}
```

React側から呼び出す例:

```ts
import { invoke } from "@tauri-apps/api/core";

const articles = await invoke<ArticleSummary[]>("get_recommended_articles");
```

## 20. Tauri権限・セキュリティ方針

### 20.1 基本方針
Tauriでは、フロントエンドからRust側機能を呼び出せるため、呼び出し可能な機能を明確に管理する。

### 20.2 注意すること
- Tauri commandを必要以上に増やさない
- 危険なファイル操作commandを安易に公開しない
- フロントから渡されたパスをそのまま信用しない
- APIキーをフロントへ返さない
- 外部URLをフロント側だけで開かない
- プラグイン追加時は権限を確認する

### 20.3 推奨
- React側は表示と操作に寄せる
- Rust側で入力検証を行う
- Rust側で外部通信先を制御する
- Rust側でログ出力を制御する
- Rust側でローカル保存先を固定する

## 24. よくあるトラブルと対応

### 24.1 gitが認識されない
原因候補:
- Git未インストール
- PowerShellを開き直していない
- PATHが反映されていない

対応:

```powershell
git --version
```

Git Bashでは動くがPowerShellで動かない場合は、PowerShellを開き直す。

### 24.2 npmがPowerShellで実行できない
原因候補:
- PowerShellの実行ポリシーにより `npm.ps1` がブロックされている

対応:

```powershell
Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
```

確認:

```powershell
Get-ExecutionPolicy -Scope CurrentUser
```

`RemoteSigned` と表示されればよい。

### 24.3 npm installに失敗する
原因候補:
- Node.jsが未導入
- Node.jsバージョンが古い
- ネットワーク制限
- package-lockの不整合

対応:

```bash
node -v
npm -v
```

必要に応じて依存関係を再インストールする。

### 24.4 Rust / Cargoが認識されない
原因候補:
- Rust未導入
- PATHが通っていない
- ターミナルを再起動していない

対応:

```bash
rustc --version
cargo --version
```

インストール後はVS Codeやターミナルを再起動する。

### 24.5 Tauri devが起動しない
原因候補:
- Microsoft C++ Build Tools不足
- WebView2不足
- Rust依存関係の取得失敗
- Node依存関係の取得失敗

対応:
- Build Toolsを確認
- WebView2 Runtimeを確認
- `npm install` を再実行
- `cargo --version` を確認
- エラーメッセージをチーム共有シートに記録

### 24.6 画面は出るがTauri commandが動かない
原因候補:
- command名の不一致
- `#[tauri::command]` の付与漏れ
- invoke側の名前間違い
- Rust側でcommand登録が漏れている
- 権限設定の不足

対応:
- Rust側のcommand名を確認
- React側の `invoke()` 名を確認
- `main.rs` の登録を確認
- エラーログを確認

### 24.7 Gemini APIが動かない
原因候補:
- APIキー未設定
- 環境変数がVS Codeに反映されていない
- 無料枠や制限に達している
- ネットワーク制限
- Rust側で環境変数参照に失敗している

対応:
- `GEMINI_API_KEY` を再設定
- VS Codeやターミナルを再起動
- MockProviderへ切替
- Rust側ログを確認
- APIキーをログに出して確認しない

### 24.8 Gitで不要な差分が大量に出る
原因候補:
- 改行コード差分
- 自動整形
- `node_modules/`
- `src-tauri/target/`
- ローカルデータ
- `.env`

対応:
- `.gitignore` を確認
- `.gitattributes` を整備
- 関係ない差分をコミットしない
