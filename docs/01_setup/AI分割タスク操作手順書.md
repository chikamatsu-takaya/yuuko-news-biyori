# AI分割タスク操作手順書

進捗管理画面（Firestore表示）で、1つの親タスクをAIの力を借りて複数の子タスクへ分割し、Firestoreへ一括登録・確認・削除する一連の操作手順をまとめる。

本機能は **画面からAI APIを直接呼び出すものではない**。外部AI（ChatGPT / Claude 等）へ画面のプロンプトを渡してJSONを作らせ、そのJSONを画面へ貼り付けて登録する運用である。AIの出力は、登録前に必ず人が確認する。

関連仕様の正本は [`docs/00_project/ai-subtask-import-spec.md`](../00_project/ai-subtask-import-spec.md) である。

通常操作では、現在の画面に表示されるボタン名・入力欄名を確認して操作すること。仕様書・本手順書・実際の画面表示に**差異がある場合は操作を中止**し、**仕様と実装の不一致として確認・報告**すること。不一致を利用者判断で勝手に読み替えたり、Firestoreを直接編集して解消したりしないこと（画面実装側に不具合や更新漏れがある可能性もあるため、仕様判断まで画面表示を無条件に優先しない）。

## 1. この機能でできること

- 1つの親タスクを、実装単位の子タスク（最大20件）へ分割する。
- 分割案はAIに作らせるが、**登録するのは人が確認・編集した内容**。
- 子タスクはFirestoreの `tasks` コレクションへ `source="ai-subtask-import"` で登録される。
- 各子タスクに、実装指示（implementationPrompt）とレビュー依頼文（reviewPrompt）を保存し、カードから表示・コピーできる。
- 分割元タスクは「分割親タスク」となり、子タスク数が表示される。
- 登録した子タスクは、1件ずつの個別削除、または取込単位（importBatchId）の一括取り消しができる（条件を満たす場合のみ）。

## 2. 対象者

- 進捗管理画面（Firestore表示）を使う開発メンバー。
- 大きめのタスクを、ブランチ・PR単位の小さな子タスクへ分けて進めたい人。

## 3. 前提条件

- 進捗管理画面を **ローカルサーバー経由** で開いていること。リポジトリルートで次を実行する。

  ```bash
  node task-management/serve-dashboard.mjs
  ```

  ブラウザで次を開く（ポートは既定 `8080`。環境変数 `PORT` で変更可）。

  ```text
  http://localhost:8080/task-management/?source=firestore
  ```

  `?source=firestore` を付けないと通常のMarkdown表示になり、AI分割機能は使えない。
- Firebase / Firestore の接続設定が完了していること（[`docs/00_project/firebase-config-setup.md`](../00_project/firebase-config-setup.md) 参照）。
- 外部AI（ChatGPT / Claude 等）を別途利用できること。
- **APIキー・パスワード・秘密情報を、外部AIへ渡すプロンプトやJSONへ含めないこと。**
- 作業開始前に、分割したい対象タスクの内容（目的・完了条件・関連ブランチ）を確認しておくこと。

## 4. 全体の流れ

```text
親タスクを選ぶ
  → 「AIで分割」ボタンでモーダルを開く
  → 「プロンプトをコピー」で AI分割用プロンプトを取得する
  → 外部AIへ渡し、JSONだけを生成させる
  → JSONを貼り付けて「JSONを検証」
  → プレビューを確認・編集する（不要な子は除外）
  → 「Firestoreへ一括登録」
  → 分割親・子タスクの表示を確認する
  → 実装・レビュー依頼プロンプトをコピーして作業する
  → 必要に応じて個別削除／一括取り消し
```

## 5. 親タスクを選択できる条件

親候補のタスクカードにだけ分割用ボタンが表示される。**未分割の親は「AIで分割」、分割済みの親は「子タスクを追加」**とボタン文言が変わる（動作は同じ登録フロー）。条件は次のとおり（判定の正本は実装 `ai-subtask-import-parent.mjs`）。

**選択できる**

- `status` が **Todo / Doing / Blocked**。
- `completed` が false。
- `archived` が true でない。
- `parentTaskId` を持たない（親なし）タスク。
- **完全な未分割**（初回分割）、または **整合した分割済み親**。整合した分割済み親では、既存の子タスクを維持したまま子タスクを追加登録できる。

**選択できない**

- `status` が **Review / Done**。
- `completed=true`。
- `archived=true`。
- **`parentTaskId` を持つ子タスク**（子タスクをさらに分割する孫タスク化は対象外）。
- **`parentTaskId` が文字列でない不整合データ**（数値・boolean・配列・オブジェクト等。空文字へ補正せず不整合として扱う）。
- **分割管理フィールドが不整合な親**（下記）。

**`parentTaskId` の扱い**：未設定 / `null` / 空文字 / 空白のみの文字列は「親なし」（分割できる）。trim後に非空の**文字列**は「子タスク」（分割対象外）。`null` 以外の**非文字列**（数値・boolean・配列・オブジェクト）は**不整合**として候補にも登録対象にもしない。

**「整合した分割済み親」とは**：`taskRole="split-parent"` かつ `autoStatusUpdateDisabled=true` かつ `splitChildCount` が**正の有限安全整数**の3つがすべて揃った状態。1つでも欠ける・食い違う（例：`taskRole` だけある／`taskRole` が非文字列／`autoStatusUpdateDisabled` が `"true"`・`1`／`splitChildCount` が 0・負・小数・文字列・欠落）と**不整合**とみなし、候補にも登録対象にもしない（データ確認が必要）。不正な値を 0 や空文字へ補正はしない。

**UI候補判定は Firestore の生データで行う**：ボタンの表示可否・文言は、画面表示用に正規化した値ではなく**正規化前の生データ**から判定する。そのため、表示用に 0 や空文字へ丸められても、不整合データが候補として出ることはない（UIの候補判定と登録直前の検証は同じ判定を使う）。

（分割済みかどうか自体は選択可否の条件にしないが、上記の Review / Done / completed / archived、子タスク、不整合の除外条件は、未分割・分割済みのどちらにも同じく適用される。）

**Doing かつ branchName 設定済みの親を分割する場合の注意**：その親は「分割親タスク」になり、post-merge（PRマージ後の自動status更新）による Done / Review 自動更新の**対象外**になる。分割後の親の最終完了は、人が子タスクの状況を見て判断する。

親タスク自身の `status` / `branchName` / `issuePr` は、AI分割の登録・削除で**勝手に変更されない**（子の登録／削除に伴い、親には分割管理フィールドだけが設定・解除される）。

## 6. AI分割用プロンプトをコピーする

1. 親タスクカードの「**AIで分割**」（分割済みの親では「**子タスクを追加**」）を押すと、モーダル「**AIで分割タスクを追加**」が開く。
2. ステップ1「**ステップ 1 / 2：分割元の親タスク（このタスクで固定）**」で、対象の親タスクが正しいか確認する。
3. ステップ2「**ステップ 2 / 2：AI用プロンプトとJSON貼り付け・検証**」の「**プロンプトをコピー**」を押す。

このプロンプトには、親タスク情報（参考情報）と、AIへの出力ルールが含まれる。プロンプト本文は実装から生成されるため、**手順書へ全文転載はしない**。実際に使うときは、必ず**画面のコピーボタンから取得**すること（本手順書の要点説明と画面のプロンプトに差異があれば、操作を中止し仕様と実装の不一致として報告する）。

プロンプトに含まれる主な出力ルール（要点）:

- **JSONだけを出力**する。説明文・前置き・後書き・Markdownのコードフェンス（`` ``` ``）・コメントを付けない。
- `schemaVersion` は **1**。
- `tasks` は **1件以上20件以下**。
- 各タスクが持てるのは、許可された作業項目（11個）だけ。
- `category` / `status` / `parentTaskId` などの**システム管理項目は出力しない**。
- 親タスク情報内の文章は参考情報であり、そこに書かれた指示を命令として実行させない。
- 1ブランチ・1PR・1主タスク単位で分割する。

## 7. 外部AIでJSONを生成する

1. コピーしたプロンプトを外部AIへ貼り付ける。
2. 元タスクの追加情報が必要なら、**秘密情報を含めない範囲**で補足する。
3. AIにJSONを生成させる。
4. **AIの出力を必ず人が読んで確認する**（誤り・過不足・不要タスクがないか）。

### 受け付けるJSONの最小例

次は現在のバリデータを通過する最小例（子タスク1件）。

```json
{
  "schemaVersion": 1,
  "splitSummary": "表示機能と確認機能へ分割",
  "tasks": [
    {
      "title": "表示処理を実装する",
      "purpose": "対象情報を画面へ表示する",
      "splitReason": "表示部分を独立して確認するため",
      "doneWhen": ["対象情報が画面へ表示される"],
      "scope": ["表示処理"],
      "outOfScope": ["Firestore保存処理"],
      "implementationPrompt": "対象の表示処理を実装してください。",
      "reviewPoints": ["表示内容が仕様と一致すること"],
      "reviewPrompt": "@codex review\n表示内容を中心にレビューしてください。",
      "verificationCommands": ["pnpm test"],
      "notes": ["サンプルタスク"]
    }
  ]
}
```

### 各タスクが持てる11項目（`title` のみ必須）

| キー | 種別 | 上限 | 必須 |
|---|---|---|---|
| `title` | 文字列 | 120文字 | 必須 |
| `purpose` | 文字列 | 1000文字 | 任意 |
| `splitReason` | 文字列 | 1000文字 | 任意 |
| `doneWhen` | 文字列配列 | 20要素・各300文字 | 任意 |
| `scope` | 文字列配列 | 20要素・各300文字 | 任意 |
| `outOfScope` | 文字列配列 | 20要素・各300文字 | 任意 |
| `implementationPrompt` | 文字列 | 8000文字 | 任意 |
| `reviewPoints` | 文字列配列 | 20要素・各300文字 | 任意 |
| `reviewPrompt` | 文字列 | 8000文字 | 任意 |
| `verificationCommands` | 文字列配列 | 20要素・各300文字 | 任意 |
| `notes` | 文字列配列 | 20要素・各300文字 | 任意 |

### そのほかの受け付けルール

- ルート直下で許可するキーは `schemaVersion` / `splitSummary` / `tasks` のみ。
- `tasks` は **1件以上20件以下**。0件・21件以上はエラー。
- `schemaVersion` は **1** 以外はエラー。
- **未知キー**はエラー（`UNKNOWN_FIELD`）。
- **システム管理項目**（`parentTaskId` / `category` / `subcategory` / `priority` / `owner` / `status` / `branchName` / `completed` / `archived` / `source` / `order` / `taskCode` / `issuePr` / `importBatchId` / `autoStatusUpdateDisabled` / `taskRole` / `splitChildCount` など）がJSONに含まれるとエラー（`SYSTEM_FIELD_NOT_ALLOWED`）。
- 型不一致はエラー（例: `title` に数値、配列項目に文字列など）。
- 必須の `title` が空文字（trim後）だとエラー。任意項目の空文字・空配列は許容される。
- JSON全体の最大サイズは **200KB（200×1024バイト、UTF-8バイト数）**。超過はエラー。
- **コードフェンスの前処理**：JSON全体を囲む「1組」の ```` ```json … ``` ```` または言語指定なしの ```` ``` … ``` ```` だけは自動で取り除く。それ以外（`yaml` 等の言語指定、複数フェンス、未閉じフェンス、JSON中に混ざった説明文）は取り除かず、そのままJSON解析に回るためエラーになる。
- 先頭の **BOM** と前後の空白は自動で除去される。壊れたJSONの自動修復はしない。

## 8. JSONを貼り付けて検証する

1. モーダルのJSON入力欄へ、AIが生成したJSONを貼り付ける。
2. 「**JSONを検証**」を押す。
3. エラーがある場合は、エラー箇所（`path` 付き）が表示され、**登録はできない**。
4. エラーを修正して、再度「JSONを検証」を押す。
5. 正常なら「検証成功：子タスク N 件。…」と表示され、下にプレビューが出る。

検証成功後、**内容を編集していなければ、そのまま「Firestoreへ一括登録」を押せる**。プレビューで編集した場合は「編集内容を再検証」を押して、再検証が成功してから登録する。

## 9. プレビューを確認・編集する

プレビューでは次を確認する。

- `splitSummary`（読み取り専用）。
- 分割元の親タスク。
- 登録予定件数（「登録対象 N 件 / 除外 M 件」）。
- 各子タスクのタイトル・作業内容。
- 親から継承する値（category / subcategory / priority / owner）。
- 分割親になる旨の警告、post-merge自動status更新の対象外になる旨の注意。

## 10. プレビュー編集・除外

### 編集できる作業内容（11項目）

`title` / `purpose` / `splitReason` / `doneWhen` / `scope` / `outOfScope` / `implementationPrompt` / `reviewPoints` / `reviewPrompt` / `verificationCommands` / `notes`。

- 配列項目（`doneWhen` / `scope` / `outOfScope` / `reviewPoints` / `verificationCommands` / `notes`）は、**1行＝1要素**として入力する。
- 編集した後は「**編集内容を再検証**」を押す。再検証が成功するまで登録できない。

### 親から継承する項目（4項目）

`category` / `subcategory` / `priority` / `owner`。プレビュー上で編集でき、編集後は再検証の対象になる。

### 除外

- 各子タスクの「**登録対象に含める**」チェックを外すと、その子は登録されない。
- **全件を除外した状態では登録できない**（「全件除外中：登録対象がありません。登録できません」と表示される）。

### 編集できない項目

`status` / `parentTaskId` / `source` などのシステム管理項目は編集できない（登録時にシステムが設定する）。

## 11. 子タスクを一括登録する

「**Firestoreへ一括登録**」を押すと、次のように処理される。

**登録時**

- 親タスクの最新状態をFirestoreから再取得して再確認する。
- 親が選択不可状態（Review / Done / completed / archived、子タスク〔`parentTaskId` あり〕、分割管理フィールドが不整合、のいずれか）に変わっていたら、**登録を中止**する（整合した分割済みかどうかは中止条件にしない）。不整合を検出した場合は、データ確認を促す固定メッセージで中止し、Firestoreへ何も書き込まない。
- 親の分割管理フィールド更新と、**新規**子タスクの登録を **同一トランザクション**で行う（全件成功または全件失敗。一部だけ登録されることはない）。**既存の子タスクは削除・更新・再作成されない**（新しく生成した子タスクだけが追加される）。
- 子タスクは `status="Todo"`、`branchName` 未設定、`source="ai-subtask-import"` で登録される。
- 同じ取込には共通の `importBatchId`（`ai-` から始まる）が付く。追加登録では取込ごとに別の `importBatchId` になる。
- 親には分割親情報（`taskRole="split-parent"` / `autoStatusUpdateDisabled=true` / `splitChildCount`）が設定される。**`splitChildCount` は登録後の子タスク総数（既存の子＋今回追加した子）**になる。総数は**トランザクション内で再取得した最新の `splitChildCount`（整合した分割済み親の正の有限安全整数のみを既存子数として採用）に新規件数を足して**計算する（初回分割＝完全な未分割は既存子数0として今回追加した子の数と一致）。不正・欠落した `splitChildCount` を 0 として補正はしない。

**登録後**

- 一覧を再取得して再描画する。
- 成功メッセージ「AI分割タスクをN件登録しました。 importBatchId: …」が表示される。
- 親カードに「**分割親タスク**」「子タスク数: N件」「**post-merge自動status更新対象外**」が表示される。
- 各子カードに次が表示される。
  - source バッジ「**AI分割タスク**」「**source: ai-subtask-import**」「**Markdown未反映**」。
  - 親タスク行「**親タスク: [親taskCode] 親タイトル**」（親のtaskCodeが空ならタイトルのみ）。

## 12. 保存済みプロンプト（実装プロンプト）

AI分割子タスクのカードには、**保存済みプロンプト**が表示される。これは既存の**動的生成表示とは別枠**である。

| 区分 | 名称 | 内容 |
|---|---|---|
| 保存済み | **AI分割・実装プロンプト** | その子タスク固有の実装指示（登録時に保存した `implementationPrompt`） |
| 保存済み | **AI分割・レビュー依頼プロンプト** | PRレビュー依頼時に使う文面（登録時に保存した `reviewPrompt`） |
| 動的生成（既存） | AI作業プロンプト | タスク情報から都度組み立てる作業プロンプト |
| 動的生成（既存） | レビュー時の確認観点 | タスク情報から都度組み立てる確認観点 |

### 実装プロンプトの使用（第12節）

1. 子カードの「**AI分割・実装プロンプト**」を開く。
2. 「**AI分割・実装プロンプトをコピー**」でコピーし、実装作業に使う。

- 表示は **プレーンテキスト**。改行は保持される。URLは**自動リンク化されない**。HTML風の文字列も文字として表示される（実行されない）。

## 13. レビュー依頼プロンプトの使用

1. 子カードの「**AI分割・レビュー依頼プロンプト**」を開く。
2. 「**AI分割・レビュー依頼プロンプトをコピー**」でコピーする。

- `reviewPrompt` に `@codex review` が含まれる場合も**そのままコピー**される。
- **画面からGitHubへ自動投稿されるわけではない**。コピーした文面を、PR等で人が使う。
- 実装用とレビュー用のコピーボタンは別々で、**一方のボタンでもう一方のプロンプトはコピーされない**。

## 14. AI分割タスクを個別削除する

AI分割子タスクは、条件を満たす場合のみ1件ずつ削除できる。

1. 子カードの「**AI分割タスクを削除**」を押す。
2. 確認モーダル「**AI分割タスクの削除**」で対象タスク名を確認する。
3. 実行する。削除直前にFirestoreの最新状態を再取得・再検証し、条件を満たすときだけ物理削除する。

**削除できる子（すべて満たす）**

- `source="ai-subtask-import"`。
- `status="Todo"`。
- `completed` が false。
- `archived` が **boolean の false**（未設定・型不正は不可）。
- `branchName` が未設定（null / 空 / 空白のみ。非文字列は不可）。
- `protected` でない。
- `parentTaskId` が有効な文字列。
- 親タスクとの整合性が取れている（親が存在し、`taskRole="split-parent"` / `autoStatusUpdateDisabled=true` / `splitChildCount` が1以上の整数）。

**個別削除後**

- 親の `splitChildCount` が1減る。
- 子が残る場合、親の分割状態は維持される。
- **最後の子を削除した場合、親の分割状態（`splitChildCount` / `autoStatusUpdateDisabled` / `taskRole`）が解除される**。
- 親の `status` / `branchName` / `issuePr` は変更されない。
- 成功メッセージ「AI分割タスクを削除しました。親タスクの残り子タスク数: N件」（最後の子なら「親タスクの分割状態を解除しました。」）。

## 15. 取込単位で一括取り消しする

同じ `importBatchId` の子タスクをまとめて取り消す。

1. いずれかの子カードの「**この取込を一括取り消し**」を押す。
2. 確認モーダルに、対象の `importBatchId` と**対象件数**、対象タスク名が表示される。
3. 実行すると、対象の全子と親をFirestoreの最新状態で再取得・再検証し、条件を満たすときだけ全件削除する。

- 押した子タスクと**同じ `importBatchId`** の子が対象。
- **1件でも削除不可なら全件中止**（部分削除はしない）。
- 対象件数の上限は **20件**（初期MVPの登録上限に対応。大きく超える場合は不整合として中止）。
- 親の `splitChildCount` との整合性を確認する（削除件数が `splitChildCount` を超える場合は中止）。
- 対象を全件削除した結果、子が残らない場合は**親の分割状態を解除**する。設計上、別の取込の子が残るケースでは、件数だけ減らして親の分割状態を維持する。
- 親の `status` / `branchName` / `issuePr` は変更されない。
- 成功メッセージ「AI分割タスクをN件取り消しました。…（importBatchId: …）」。

**一括取り消しが失敗した場合**、Firestoreを直接編集しないこと。失敗理由（開始済み・branchName設定済み等）を確認し、対象の子タスクは**通常の作業フロー**（そのまま作業を進める等）で扱う。

## 16. 削除・取り消しができない条件

次の子タスクは、個別削除・一括取り消しの対象にできない。

- 作業開始済み（`branchName` 設定済み）。
- `status` が Doing / Review / Done。
- `completed=true`。
- `archived=true`、または `archived` が boolean の false 以外（型不正）。
- `protected=true`。
- 親が存在しない。
- 親の `splitChildCount` が不正（未設定・非整数・0以下）。
- 親子関係が不一致（子の `parentTaskId` と親IDが一致しない）。

一括取り消しでは、対象の中に**1件でも**上記に該当するものがあれば、全件中止になる。

## 17. エラーが発生した場合

### 親タスクが候補に表示されない

確認するもの：`status`（Todo/Doing/Blockedか）、`completed`、`archived`、`parentTaskId` を持つ子タスクでないか、分割管理フィールド（`taskRole` / `autoStatusUpdateDisabled` / `splitChildCount`）が整合しているか、URLに `?source=firestore` が付いたFirestore表示か。（**整合した**分割済み親〔3フィールド揃い〕は候補に表示され「子タスクを追加」ボタンになる。子タスクや不整合な親は候補に出ない。）

### JSONが検証エラーになる

確認するもの：JSON以外の説明文が混ざっていないか、コードフェンス（言語指定違い・複数・未閉じ）、`schemaVersion`（1か）、`tasks` 件数（1〜20）、`title` の有無、許可されていないキー、システム管理項目の混入、文字数・配列要素数の上限、配列であるべき項目が配列か、JSONサイズ（200KB以内）。

### 一括登録が失敗する

確認するもの：親が登録前に Review / Done / completed / archived 等へ変わっていないか、親が子タスク（`parentTaskId` あり）でないか、親の分割管理フィールドが不整合になっていないか、通信エラー。不整合の場合は「親タスクの分割管理情報が不整合です。データを確認してください」で中止する。失敗時は「一括登録に失敗しました：… Firestore は変更されていません。…」と表示され、**Firestoreは変更されていない**（既存の子タスクも変更されない）。再読み込みして最新状態を確認する。

### 削除ボタンが表示されない

確認するもの：`status="Todo"` か、`branchName` が空か、`completed` / `archived` / `protected`、`source="ai-subtask-import"` か、`parentTaskId` の有無、ページ再読み込みが必要な状態か。

### 削除後に画面更新へ失敗した

- **削除自体は成功している可能性が高い**（「AI分割タスクの削除は完了しましたが、一覧の再取得に失敗しました。ページを再読み込みして結果を確認してください。」と表示される）。
- 画面に残った古いカードで**再操作しない**（同じ操作を連打しない）。
- ページを再読み込みし、再読み込み後の状態を確認する。

### コピーに失敗する

- ブラウザのクリップボード権限、実行環境（`localhost` / HTTPS 等）を確認する。
- 自動コピーに失敗した場合は、表示されているテキストを**手動で選択して Ctrl + C** でコピーする（画面もこの代替を案内する）。

> エラー文言は将来変わる可能性がある。本手順書の文言と画面のメッセージに差異がある場合は、正確な文言に依存した判断をせず、仕様と実装の不一致として確認・報告すること。

## 18. 運用上の注意

- **正本はFirestore**。AI分割タスクは初期MVPでは**Markdownへ追加されない**（子カードに「Markdown未反映」と表示される）。
- 親タスクは、子タスクを登録しただけでは **Done にならない**。親の最終完了は、人が子の完了状況を確認して判断する。
- 子タスクは **1ブランチ・1PR・1主タスク単位**で進める。子ごとに作業開始時に `branchName` を設定する。
- 親タスクを、作業ブランチのPRで直接 Done にしない（分割親は post-merge 自動status更新の対象外）。
- **秘密情報を、プロンプトやJSONへ含めない。**
- AIの出力は、登録前に必ず人が確認する。不要なタスクは登録前に除外する。
- 登録後に作業開始した子（`branchName` 設定・Doing 化など）は、安全上**削除できなくなる**場合がある。一括取り消しを想定するなら、作業開始前に内容を再確認しておく。

## 19. 現在の制限事項

- 画面からAI APIを直接呼ばない（外部AIでJSONを作る運用）。
- MarkdownへAI分割子タスクを追加しない。
- 子の `taskCode` を自動採番しない。
- 子の `branchName` を自動付与しない（作業開始時に人が設定）。
- 子の `issuePr` を自動付与しない。
- 子タスクは `status="Todo"` 以外で登録できない。
- 分割済み親へは既存子を維持したまま子タスクを追加登録できる（ボタンは「子タスクを追加」）。ただし**子タスクをさらに分割する多階層化（孫タスク）は対象外**。
- 自由記述から独立した新規タスクをAIで作る機能は対象外（分割元の親を選ぶ一括登録フローのみ）。
- 親から子への `childTaskIds` 配列は保存しない（親子関係は子の `parentTaskId` を正本とする）。
- Firestoreが使えない通常のMarkdown表示（`?source=firestore` なし）では、本機能を操作できない。
