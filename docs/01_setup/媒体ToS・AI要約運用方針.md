# 媒体ToS・AI要約 運用方針

最終更新: 2026-06-10
対象: ニュースソースの追加・利用と、AI要約・保存・表示の運用範囲
前提: 製品デフォルトは deny-by-default（取得元ゼロ）。実取得は app-data の検証用設定で有効化する（[ニュースソース設定手順](ニュースソース設定手順.md)）。

## 1. 目的
- ニュース媒体の **ToS / 利用規約** と、本アプリの **保存・AI要約・表示** の運用範囲を明文化する。
- **MVP（検証/開発）** と **公開版（社内配布以降）** で運用範囲を分けて示す。
- ニュースソース追加時に確認すべき観点（ToS・AI要約可否）を定義する。

## 2. 基本原則（MVP・公開版 共通）
- 取得元は **許可リスト方式（deny-by-default）** で管理する（セキュリティ詳細設計書 §6）。可否不明な媒体は追加しない。
- ソフト内では **原文の大量表示・転載を避け**、ゆうこの再説明文・要点整理・注目ポイント中心で表示する（CLAUDE.md §5.3）。原文確認は **出典リンクへ誘導**し、ユーザー操作で開く（AI出力内URLは自動リンク化しない）。
- AI送信は **Rust側で最小化**する（指示＋本文抜粋のみ。本文全文・選択文字列全文・秘密情報は送らない＝セキュリティ詳細設計書 §7）。
- APIキー等の秘密情報はコード / Git / ログ / Markdown に残さない（同 §8）。

## 3. MVP（検証/開発）と 公開版 の運用範囲
| 観点 | MVP（検証/開発） | 公開版（社内配布以降） |
|---|---|---|
| 取得元 | 検証用に **1媒体（Publickey）** を許可リストで限定（PR #35）。ToS確認は開発者の責任で実施 | 追加媒体ごとに **ToS/規約を確認**し、可否を判断して許可リスト化（→ §4） |
| 保存 | 1記事1Markdown（**本文抜粋**＋AI生成＋メタ）をローカル保存。1か月経過で月次ZIP化（お気に入り除外・データ設計書 §14） | 媒体規約に応じて **保存可否・保存範囲（抜粋長）** を調整。規約で保存不可なら取得対象から除外 |
| AI要約（送信） | Geminiキー設定時のみ実AI（指示＋**抜粋**のみ送信）。未設定はMock。送信は最小限 | 同左を維持。媒体が **AI処理（要約）を禁止** する場合は当該媒体をAI要約対象から外す（取得自体の可否も含め判断） |
| 表示 | 再説明文・要点・注目ポイント・用語補足中心。原文は出典リンク誘導 | 同左。**原文転載に相当する表示を作らない**。規約の引用範囲・帰属表示（出典明記）を順守 |
| 配布 | ローカル検証のみ（リポジトリ／製品デフォルトは deny-by-default 維持） | 社内配布。媒体規約・社内方針の確認後に取得元を有効化 |

## 4. ニュースソース追加時の確認チェックリスト（ToS・AI要約可否）
新しい取得元を許可リストへ追加する前に、媒体の ToS / 利用規約を確認し、以下を記録する。

- [ ] **規約の所在**: 媒体のToS/利用規約・RSS提供条件のURLを確認した
- [ ] **取得可否**: RSS/フィード取得・記事本文（HTML）取得が規約上許容される
- [ ] **保存可否**: 本文抜粋のローカル保存・キャッシュが許容される（不可ならタイトル/出典/URL中心に留め、抜粋を持たない）
- [ ] **AI要約可否**: 記事内容を外部AI（Gemini等）へ送って要約・再説明することが許容される（不可なら当該媒体はAI要約対象外）
- [ ] **表示・帰属**: 引用範囲の制限・出典明記（帰属表示）の要件を満たす。原文転載相当の表示はしない
- [ ] **再配布**: 取得物の再配布・第三者提供をしない（ローカル利用に限定）
- [ ] **許可リスト更新**: フィードと記事の **両ドメイン** を `network_allowlist.json` に追加した
- [ ] **疎通確認**: ローカルで取得結果（`fetched` / `saved` / `errors`）を確認した

> 1つでも「可否不明」が残る場合は許可リストへ追加しない（deny-by-default を維持）。
