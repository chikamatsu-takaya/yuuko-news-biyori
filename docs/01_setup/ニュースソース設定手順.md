# ニュースソース設定手順（検証用）

最終更新: 2026-06-05
対象: 開発・検証環境でニュースの実取得を有効化する手順
前提: 製品デフォルトは deny-by-default（取得元ゼロ）。本手順は app-data に検証用設定を置いて実取得を有効化するもので、コードのデフォルトには焼き込まない。

## 1. 仕組みの前提
- 取得元（フィードURL）は `config/news_sources.json` を **唯一の正** として管理する。
- 外部通信の可否は `config/network_allowlist.json`（許可リスト方式・deny-by-default）で制御する。
- どちらも **破損時は fail-close**（取得を中止）。BOM付きUTF-8は許容する。
- 初回起動時に、両ファイルの安全なデフォルト（空 / deny-by-default）が自動生成される。
- 取得タイミングは「起動時 ＋ 日付変更時（低頻度チェック）」。手動更新はホーム画面の更新UIから（`refresh_news`）。

## 2. 設定ファイルの場所
Tauri の app-data 配下に置く。

- Windows: `%APPDATA%\com.tauri.dev\config\`
  - 例: `C:\Users\<ユーザー名>\AppData\Roaming\com.tauri.dev\config\`
- 正確な場所は、起動ログの `Backend initialized. storage_root=...` で確認できる。
- 対象ファイル: `config/news_sources.json` / `config/network_allowlist.json`

> 注: `com.tauri.dev` は現状の Tauri 既定 identifier。将来、正式 identifier へ変更した場合はパスも変わる。

## 3. 設定手順
1. アプリを一度起動し、デフォルト設定ファイルを生成させる（または手動で作成する）。
2. `config/news_sources.json` に取得元を追加する。
3. `config/network_allowlist.json` の許可ドメインに、**フィードと記事の両方のドメイン**を追加する。
4. **UTF-8 で保存**する（BOM 有無どちらでも可。BOM は許容される）。
5. アプリを再起動 → 起動時取得、またはホーム画面の更新UIで取得する。

### 3.1 `news_sources.json`（例: Publickey）
```json
{
  "version": 1,
  "sources": [
    { "url": "https://www.publickey1.jp/atom.xml", "genre": "テクノロジー" }
  ]
}
```
- `url`: フィードURL（RSS2.0 / Atom の両対応）
- `genre`: 記事に付与するジャンル（おすすめ採点・表示に使用）

### 3.2 `network_allowlist.json`（例: Publickey）
```json
{
  "version": 1,
  "allowedRssDomains": ["www.publickey1.jp"],
  "allowedArticleDomains": ["www.publickey1.jp"],
  "allowedAiEndpoints": ["generativelanguage.googleapis.com"],
  "blockedSchemes": ["file", "ftp", "data", "javascript"]
}
```
- `allowedRssDomains`: フィード取得を許可するドメイン
- `allowedArticleDomains`: 記事HTML取得を許可するドメイン（**未許可だとその記事は保存されない**）
- 一致判定は「完全一致 または サブドメイン一致」（例: `example.com` は `news.example.com` も許可）

## 4. 反映確認
- 取得記事は `<storage_root>\news\<YYYYMM>\<articleId>.md` に保存される。
- メイン画面のニュース一覧に表示される。
- `refresh_news` の結果（更新UI / ログ）で `fetched` / `saved` / `errors` を確認できる。

## 5. うまく取得できないとき
`errors` のカテゴリで切り分ける（内部詳細はログのみ。UIには種別のみ返る）:

| kind | 意味 | 対処 |
|---|---|---|
| `feed_url_rejected` | フィードURLが許可リスト外 | `allowedRssDomains` を確認 |
| `feed_fetch_failed` | フィード取得失敗 | URL・ネットワーク・フィード形式（RSS2.0/Atom）を確認 |
| `article_url_rejected` | 記事URLが許可リスト外 | `allowedArticleDomains` を確認 |
| `article_fetch_failed` | 本文取得失敗（保存は継続） | 一時的失敗のことが多い。次回取得で解消する場合あり |

- 取得0件: 取得元が空 / 許可リスト未設定 / ドメイン不一致 が典型。
- 全取得が止まる: `news_sources.json` または `network_allowlist.json` のJSONが壊れている（fail-close）。構文を確認する。

## 6. セキュリティ・運用上の注意
- 許可リストは **必要最小限**にする。記事ドメインの追加も忘れない。
- 取得元の追加は、媒体の **ToS / 利用条件** を確認のうえ行う（RSS取得・ローカル保存・AI要約の可否）。
- 取得は低頻度（起動時＋日付変更時）。高頻度ポーリングはしない。
- 本設定は **検証用のローカル配置**。製品デフォルト（deny-by-default）は変更しない。
