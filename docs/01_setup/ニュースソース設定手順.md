# ニュースソース設定手順（検証用）

最終更新: 2026-10-19
対象: 既定の取得元の仕組みと、開発・検証環境で取得元を差し替える手順
前提: 新規インストール時（取得元設定ファイルが無いとき）だけ、アプリ同梱の既定取得元（判断台帳 D138・RSS 11件）が書き出される。既存の設定ファイルは上書き・マージしない。本手順の検証用設定は app-data に置くもので、コードの既定値には焼き込まない。

## 1. 仕組みの前提
- 取得元（フィードURL）は `config/news_sources.json` を **唯一の正** として管理する。
- 外部通信の可否は `config/network_allowlist.json`（許可リスト方式・deny-by-default）で制御する。
- どちらも **破損時は fail-close**（取得を中止）。BOM付きUTF-8は許容する。
- 初回起動時に、ファイルが無いものだけ自動生成される（§1.1）。
- 取得タイミングは「起動時 ＋ 日付変更時（低頻度チェック）」。手動更新はホーム画面の更新UIから（`refresh_news`）。

### 1.1 既定の取得元（D138）
- `config/news_sources.json` が **無いときだけ**、起動時に同梱の既定取得元（下表）を書き出す。定義は `src-tauri/src/services/default_news_sources.rs`。
- `config/network_allowlist.json` も同じ起動で新規作成する場合だけ、下表のフィード／記事ホストだけを登録した内容で書き出す（親ドメインは登録しない）。許可リストが既にある場合は触れない。
  - 照合は既存の `url_guard` の仕様どおり「完全一致 または サブドメイン一致」で、http / https を受け付ける。そのため登録ホストが媒体の基底ドメインである `gigazine.net`・`toyokeizai.net`・`sorae.info`・`full-count.jp` は、同じ媒体のサブドメインも許可される（ローカル/プライベートIP拒否・DNS rebinding 対策は変わらず適用される）。
- 一度書き出した後は、ファイルの内容が唯一の正。既定値で上書き・マージしない（ユーザーの編集が常に勝つ）。
  - 取得元を空配列にした場合も空のまま（取得しない）。旧版が自動生成した空の設定も同じ扱いのため、既定取得元を使いたい場合は両ファイルを削除（または退避）して再起動する。
  - 取得元設定だけを削除すると、取得元は既定値になるが許可リストは既存のまま。許可されていない取得元は `feed_url_rejected` になる。
- 既定値も通常の設定と同じ検証（http / https のみ・許可ホスト一致・ローカル/プライベートIP拒否・受信上限）を通る。
- 書き出しは一時ファイル経由で一度に置き換える（書きかけのファイルを残さない）。書き出しに失敗しても起動は続け、取得は行わない（次回起動で再作成を試みる）。
- ジャンルは設定画面の興味ジャンルの選択肢と同じ値（国際〜暮らしは D141 で選択肢に追加）。興味ジャンルの絞り込み（D10）の対象で、既定の興味ジャンル（AI / IT）では IT の2件だけを取得する。他の取得元は設定画面で該当ジャンルを選ぶと取得される。

## 2. 設定ファイルの場所
Tauri の app-data 配下に置く。

- Windows: `%APPDATA%\jp.star-system.yuuko-news\config\`
  - 例: `C:\Users\<ユーザー名>\AppData\Roaming\jp.star-system.yuuko-news\config\`
- 正確な場所は、起動ログの `Backend initialized. storage_root=...` で確認できる。
- 対象ファイル: `config/news_sources.json` / `config/network_allowlist.json`

> 注: 本アプリの正式 identifier は `jp.star-system.yuuko-news`（`src-tauri/tauri.conf.json`）。
> 以前の開発既定 `com.tauri.dev` 配下に作成済みの検証データは自動移行されない。identifier 変更後は
> `pnpm run setup:dev-news-source` を再実行するか、旧フォルダ `%APPDATA%\com.tauri.dev\` の中身を
> 新フォルダ `%APPDATA%\jp.star-system.yuuko-news\` へ手動移動する。

## 3. 推奨: コマンドで検証用設定を作成する
リポジトリルートで次を実行する。

```powershell
pnpm run setup:dev-news-source
```

このコマンドは、現在の `src-tauri/tauri.conf.json` の `identifier` を読み取り、app-data 配下へ Publickey 検証用の2ファイルを作成する。

- `config/news_sources.json`
- `config/network_allowlist.json`

安全のため、既存ファイルが同じ内容なら `unchanged`、違う内容なら停止する。既存設定を上書きしたい場合だけ、内容を確認してから明示的に `--force` を付ける。

```powershell
pnpm run setup:dev-news-source -- --force
```

書き込み先を確認するだけなら `--dry-run` を使う。
既存ファイルが違う内容の場合も書き込まず、`would-conflict` として表示する。

```powershell
pnpm run setup:dev-news-source -- --dry-run
```

app-data 以外の検証用ディレクトリへ出したい場合は `--app-data-dir` で明示する。

```powershell
pnpm run setup:dev-news-source -- --app-data-dir "C:\tmp\yuuko-app-data"
```

> 注: このコマンドは開発・検証用のローカル設定作成だけを行う。リポジトリ内の既定取得元（§1.1）は変更しない。

## 4. 手作業で設定する場合
1. アプリを一度起動し、設定ファイルを生成させる（新規なら既定取得元入り。または手動で作成する）。
2. `config/news_sources.json` に取得元を追加する。
3. `config/network_allowlist.json` の許可ドメインに、**フィードと記事の両方のドメイン**を追加する。
4. **UTF-8 で保存**する（BOM 有無どちらでも可。BOM は許容される）。
5. アプリを再起動 → 起動時取得、またはホーム画面の更新UIで取得する。

### 4.1 `news_sources.json`（例: Publickey）
```json
{
  "version": 1,
  "sources": [
    { "url": "https://www.publickey1.jp/atom.xml", "genre": "テクノロジー" }
  ]
}
```
- `url`: フィードURL（RSS 2.0 / RSS 1.0（RDF）/ Atom に対応）
- `genre`: 記事に付与するジャンル（おすすめ採点・表示に使用）

### 4.2 `network_allowlist.json`（例: Publickey）
```json
{
  "version": 1,
  "allowedRssDomains": ["www.publickey1.jp"],
  "allowedArticleDomains": ["www.publickey1.jp"],
  "allowedAiEndpoints": ["generativelanguage.googleapis.com"],
  "blockedSchemes": ["file", "ftp", "data", "javascript"]
}
```
- `allowedRssDomains`: フィード取得を許可するドメイン
- `allowedArticleDomains`: 記事HTML取得を許可するドメイン（**未許可だとその記事は保存されない**）
- 一致判定は「完全一致 または サブドメイン一致」（例: `example.com` は `news.example.com` も許可）

## 5. 反映確認
- 取得記事は `<storage_root>\news\<YYYYMM>\<articleId>.md` に保存される。
- メイン画面のニュース一覧に表示される。
- `refresh_news` の結果（更新UI / ログ）で `fetched` / `saved` / `errors` を確認できる。

## 6. うまく取得できないとき
`errors` のカテゴリで切り分ける（内部詳細はログのみ。UIには種別のみ返る）:

| kind | 意味 | 対処 |
|---|---|---|
| `feed_url_rejected` | フィードURLが許可リスト外 | `allowedRssDomains` を確認 |
| `feed_fetch_failed` | フィード取得失敗 | URL・ネットワーク・フィード形式（RSS 2.0 / RSS 1.0（RDF）/ Atom）を確認 |
| `article_url_rejected` | 記事URLが許可リスト外 | `allowedArticleDomains` を確認 |
| `article_fetch_failed` | 本文取得失敗（保存は継続） | 一時的失敗のことが多い。次回取得で解消する場合あり |

- 取得0件: 取得元が空（旧版から使っている環境は空のまま。§1.1）/ 許可リスト未設定 / ドメイン不一致 / 興味ジャンルに合う取得元が少ない が典型。
- 全取得が止まる: `news_sources.json` または `network_allowlist.json` のJSONが壊れている（fail-close）。構文を確認する。
- `pnpm run setup:dev-news-source` が既存ファイル差分で止まる: 既存設定を保護している状態。`-- --dry-run` で `would-conflict` の対象を確認し、上書きしてよい場合だけ `-- --force` を付ける。

## 7. セキュリティ・運用上の注意
- 許可リストは **必要最小限**にする。記事ドメインの追加も忘れない。
- 取得元の追加は、媒体の **ToS / 利用条件** を確認のうえ行う（RSS取得・ローカル保存・AI要約の可否）。確認観点と MVP/公開版の運用範囲は [媒体ToS・AI要約運用方針](媒体ToS・AI要約運用方針.md) を参照。
- 取得は低頻度（起動時＋日付変更時）。高頻度ポーリングはしない。
- 本設定は **検証用のローカル配置**。リポジトリ内の既定取得元（§1.1）は変更しない。既定取得元を変えるときは、`default_news_sources.rs` の定義・テスト・本書の表をそろえて更新する。
- Tauri command として任意設定書き込み口は公開しない。開発者向けのローカルスクリプトでのみ扱う。
