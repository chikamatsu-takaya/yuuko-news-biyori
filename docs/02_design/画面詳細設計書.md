## 3. 画面共通方針

### 3.1 UI全体の基本方針
- 画面は柔らかく、親しみやすく、硬すぎない印象にする。
- 情報を詰め込みすぎず、余白を確保する。
- ゆうこはアプリ体験の中心であり、単なる装飾にしない。
- ただし、ニュース本文や設定項目の可読性を妨げない。
- 常駐アプリとして軽量に動作することを意識する。
- 過度なアニメーションや大量描画は避ける。
- React側に業務ロジックを持たせすぎない。
- 外部通信、AI呼び出し、ローカル保存はRust側で行う。

### 3.2 色・雰囲気
初期案として、以下の雰囲気を想定する。

- クリーム系
- 淡いグリーン系
- やわらかい白背景
- 角丸カード
- 強すぎない影
- 情報カードは見やすく、やや丸みを持たせる

### 3.3 操作方針
- 主操作は大きめ・分かりやすく配置する。
- 削除やリセットなどの危険操作は、目立ちすぎない位置に置き、確認ダイアログを挟む。
- 閉じる操作はアプリ終了ではなく、原則バックグラウンド待機へ戻る。
- ユーザーが迷わないよう、戻る導線を必ず用意する。
- 外部ブラウザを開く操作は、ユーザー操作を挟む。
- AI生成や保存処理は、処理中状態と失敗時表示を用意する。

### 3.4 React / TypeScript実装方針
- 画面単位で `screens/` にReactコンポーネントを分ける。
- 共通UIは `components/` に切り出す。
- モーダルやポップアップは `dialogs/` に切り出す。
- Tauri command呼び出しは `services/` に集約する。
- 型定義は `types/` に分ける。
- 画面コンポーネントにRSS取得、AI API呼び出し、ファイルI/Oを書かない。
- APIキーや秘密情報をReact側へ渡さない。
- `dangerouslySetInnerHTML` は原則使用しない。
- UI状態と永続状態を混同しない。

### 3.5 Rust / Tauri command接続方針
- 画面表示に必要なデータはTauri command経由で取得する。
- 入力値の最終検証はRust側で行う。
- ファイル保存、設定保存、辞書保存、既読更新、ポイント加算はRust側で確定する。
- React側は処理結果を表示に反映する。
- command失敗時に画面全体がクラッシュしないようにする。

# 5. SCR-001 メイン画面

## 5.1 目的
メイン画面は、本アプリのハブ画面である。  
今日のおすすめニュース、ゆうこの状態、友情ランク、各機能への導線を一画面で確認できるようにする。

## 5.2 MVPでの役割
MVPでは、以下の体験を見せる中心画面とする。

- 今日のおすすめニュースを確認する。
- ゆうこが画面内に存在する。
- ニュース閲覧画面へ遷移する。
- 辞書、履歴、設定へ移動する。
- 友情ランク進捗を確認する。

## 5.3 レイアウト方針
### 基本配置
- ゆうこ本体は **画面中央下寄り** を基本位置とする。
- 左側から中央にかけてニュース一覧を配置する。
- 右側または上部に友情ランク、未読数、かけら数などの状態表示を置く。
- 下部またはサイドに主要メニュー導線を置く。

### 推奨構成
```text
上部:
  アプリ名 / 今日の日付 / 状態表示

左〜中央:
  今日のおすすめニュースカード一覧

右側:
  友情ランク
  次ランクまでの進捗
  未読数
  流れ星のかけら数
  ゆうこの一言

中央下:
  ゆうこ本体

下部:
  辞書 / 履歴 / 設定 / カスタマイズ / ガチャ導線
```

## 5.4 表示項目
| 項目 | 必須 | 備考 |
|---|---|---|
| アプリ名 | 必須 | 「ゆうこのニュース日和」 |
| 今日のおすすめニュース一覧 | 必須 | 10件前後 |
| ニュースカード | 必須 | タイトル、出典、要約、ジャンル |
| ゆうこ本体 | 必須 | 中央下寄り |
| ゆうこの一言 | 必須 | 今日のおすすめや軽い案内 |
| 友情ランク | 任意 | 追加機能（MVP必須外・実装済み。MVPでは簡易表示） |
| 次ランクまでの進捗 | 任意 | 追加機能（MVP必須外・実装済み。プログレスバー） |
| 未読数 | 任意 | MVPでは簡易 |
| 流れ星のかけら数 | 任意 | MVPではダミー可 |
| 設定導線 | 必須 | 設定画面へ |
| 辞書導線 | 必須 | ゆうこ辞書画面へ |
| 履歴導線 | 必須 | ニュース履歴画面へ |
| カスタマイズ導線 | 任意 | 後続でも可 |
| ガチャ導線 | 任意 | 後続でも可 |

## 5.5 操作項目
| 操作 | 挙動 |
|---|---|
| ニュースカードクリック | ニュース閲覧画面へ遷移 |
| 設定ボタンクリック | 設定画面へ遷移 |
| 辞書ボタンクリック | ゆうこ辞書画面へ遷移 |
| 履歴ボタンクリック | ニュース履歴画面へ遷移 |
| 閉じる | バックグラウンド待機へ戻る |
| ゆうこクリック | ゆうこの一言または簡易反応を表示 |

## 5.6 初期表示
- 起動後、ニュース取得が完了している場合はおすすめニュースを表示する。
- ニュース取得に失敗している場合は、保存済みニュースを表示する。
- ニュースが1件もない場合は、空状態メッセージを表示する。

## 5.7 状態別表示
| 状態 | 表示 |
|---|---|
| ニュースあり | おすすめニュース一覧を表示 |
| ニュースなし | 「まだニュースがないみたい」等の案内 |
| 取得中 | 読み込み表示 |
| 取得失敗 | 既存ニュース表示 + 軽いエラー表示 |
| ランクアップ未確認 | ゆうこまたはバッジで通知 |
| ガチャ可能 | MVPでは非表示またはダミー |

## 5.8 エラー時表示
- ニュース取得失敗時は、画面全体をエラーにしない。
- 「ニュース取得に失敗したけど、前に取ったニュースは読めるよ」程度の案内を表示する。
- AI要約未生成の記事は、要約欄に「要約準備中」などを表示する。

## 5.9 遷移
| 遷移先 | 条件 |
|---|---|
| ニュース閲覧画面 | ニュースカード選択 |
| 設定画面 | 設定ボタン |
| ゆうこ辞書画面 | 辞書ボタン |
| ニュース履歴画面 | 履歴ボタン |
| バックグラウンド待機 | 閉じる |

| ガチャ画面 | 後続 |

# 6. SCR-002 ニュース閲覧画面

## 6.1 目的
ニュース閲覧画面は、ニュースをソフト内で読みやすく理解するための画面である。  
原文本文そのものを大量表示するのではなく、AI要約、ゆうこの再説明、要点整理、注目ポイント、用語解説を中心に表示する。

## 6.2 MVPでの役割
MVPでは、最も重要な実用画面とする。

- AI要約を読む。
- ゆうこの再説明を見る。
- 気になる用語を選択する。
- 用語解説ポップアップを表示する。
- お気に入り登録する。
- 元記事へ移動する。

## 6.3 レイアウト方針
### 推奨構成
```text
上部:
  タイトル / 出典 / 日時 / ジャンル / お気に入り / 元記事リンク

中央左〜中央:
  AI要約
  ゆうこの再説明
  要点整理
  注目ポイント
  ゆうこの感想

右側:
  ゆうこ本体
  吹き出し
  用語解説補助
  関連操作

下部:
  戻る / 前後移動 / 閉じる
```

## 6.4 表示項目
| 項目 | 必須 | 備考 |
|---|---|---|
| 記事タイトル | 必須 | 上部表示 |
| 出典 | 必須 | 出典名 |
| URL | 必須 | 元記事リンク |
| 取得日時 | 必須 | 可能なら公開日時も |
| ジャンル | 必須 | IT / AIなど |
| AI要約 | 必須 | 1〜3文 |
| ゆうこの再説明文 | 必須 | 少し長め |
| 要点整理 | 必須 | 箇条書き |
| 注目ポイント | 必須 | 学びや驚き要素 |
| ゆうこの感想 | 重要 | 社内アプリらしさ |
| お気に入りボタン | 必須 | フラグ切替 |
| 用語解説導線 | 必須 | 範囲選択後表示 |
| 元記事リンク | 必須 | 原文確認用 |
| ゆうこ本体 | 必須 | 右下寄り |

## 6.5 操作項目
| 操作 | 挙動 |
|---|---|
| 戻る | 遷移元へ戻る |
| 閉じる | バックグラウンド待機へ |
| 元記事リンク | 外部ブラウザを開く |
| お気に入り | favoriteフラグ切替 |
| 文字列選択 | 解説ボタン表示 |
| 解説ボタン押下 | 用語解説ポップアップ表示 |
| 辞書を見る | ゆうこ辞書画面へ |

## 6.6 初期表示
- 選択された記事の情報を表示する。
- AI要約が未生成の場合は「要約準備中」または生成処理を開始する。
- 読了状態を `DetailViewed` に更新する。

## 6.7 状態別表示
| 状態 | 表示 |
|---|---|
| 要約生成済み | 要約欄に表示 |
| 要約未生成 | 準備中表示 |
| AI失敗 | 要約なし + 軽い案内 |
| 本文抜粋なし | タイトル・出典・RSS概要中心 |
| お気に入り済み | ボタンを選択状態にする |
| 用語選択中 | 解説ボタンを表示 |

## 6.8 エラー時表示
- AI要約失敗時は、記事自体は表示する。
- 元記事リンクが無効な場合はリンクを非活性にする。
- 用語解説失敗時はポップアップ内で再選択案内を表示する。

## 6.9 遷移
| 遷移先 | 条件 |

# 7. SCR-003 設定画面

## 7.1 目的
設定画面は、ユーザーがアプリの動作を調整するための画面である。

## 7.2 MVPでの役割
- 関心カテゴリを設定する。
- 通知ON/OFFを設定する。
- 解説レベルを設定する。
- AI Providerを切り替える。
- テーマ設定の枠を用意する。

## 7.3 レイアウト方針
```text
左側:
  設定カテゴリ一覧

右側:
  選択カテゴリの設定項目

下部:
  保存 / キャンセル / リセット

  小さめのゆうこ、または一言
```

## 7.4 表示項目
| 項目 | MVP | 備考 |
|---|---|---|
| 関心カテゴリ | 必須 | IT / AI |
| 通知ON/OFF | 必須 | 簡易 |
| 解説レベル | 必須 | simple / normal / detailed |

| テーマ設定 | 任意 | 枠だけでも可 |

## 7.5 操作項目
| 操作 | 挙動 |
|---|---|
| 保存 | Rust側で設定JSONに保存 |
| キャンセル | 変更破棄して戻る |
| リセット | 確認ダイアログ表示 |
| AI接続テスト | GeminiまたはMockの応答確認 |
| 戻る | メイン画面へ |

## 7.6 初期表示
- 現在の `settings.json` をRust側から読み込んで表示する。
- 設定ファイルがない場合は初期値で表示する。
- APIキーが未設定の場合は、Geminiは警告表示またはMock推奨表示にする。

## 7.7 状態別表示
| 状態 | 表示 |
|---|---|
| 設定保存済み | トースト通知 |
| 設定変更あり | 保存ボタンを有効化 |
| APIキー未設定 | Gemini利用不可案内 |
| Mock選択中 | 開発用である旨を表示 |
| 保存失敗 | エラー表示 |

## 7.8 エラー時表示
- 設定保存に失敗した場合、変更前設定を維持する。
- API接続テスト失敗時は、アプリ全体を止めずに警告を表示する。

## 7.9 遷移
| 遷移先 | 条件 |

# 16. 画面レビュー観点

## 16.1 全画面共通
- 何の画面か分かるか
- 主操作が分かるか
- 戻る導線があるか
- ゆうこが邪魔になっていないか
- 文字が読みやすいか
- 情報が詰まりすぎていないか
- MVP範囲を超えて作り込みすぎていないか
- React側に業務ロジックが混ざっていないか
- Tauri command失敗時の表示があるか

## 16.2 ニュース閲覧画面
- 原文大量表示になっていないか
- 要約と再説明の違いが分かるか
- 用語解説導線が自然か
- 元記事リンクが明確か
- 元記事リンクを勝手に自動で開かないか

## 16.3 設定画面
- 設定項目が多すぎないか
- 保存と戻るが分かりやすいか
- APIキーや秘密情報を表示していないか
- AI Providerの違いが分かるか

## 16.4 辞書画面
- 見返しやすいか

# 18. まとめ
本書では、Tauri版MVPで必要となる主要画面の詳細仕様を定義した。

MVPで最も重要な画面体験は以下である。

```text
メイン画面
  ↓
ニュース閲覧画面
  ↓
用語解説ポップアップ
  ↓
ゆうこ辞書
```

これに加えて、ゆうこ通知、ニュース軽量プレビュー、ランクアップ通知を組み合わせることで、  
**ゆうこがニュースを届け、AIが読みやすくし、難しい用語をその場で解説する**  
という本アプリの中心体験を実現する。

Tauri版では、React / TypeScriptが画面表示とユーザー操作を担当し、Rust側が外部通信、AI連携、保存、状態更新を担当する。  
画面実装時は、React側に業務ロジックを持たせすぎず、Tauri commandを通じて安全にRust側処理へ接続することを基本とする。
