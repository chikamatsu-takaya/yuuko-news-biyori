## 2. ネットワーク境界（§6）
- 外部通信は **deny-by-default 許可リスト**（`network_allowlist.json`）で制御。破損時 fail-close。
- URL/スキーム検証・private/loopback/link-local IP 拒否・DNS解決後の実IP再検証・リダイレクト非追従（各 `Location` を検証）。
- Gemini エンドポイントは**固定**（`generativelanguage.googleapis.com`）＋許可リスト(AiEndpoint)検証＋リダイレクト無効。呼び出し側からURLを受け取らない。
- 判定: ✅ 既存実装（PR #22 系）で担保。本点検で公開口の増加なしを再確認。

## 3. AI送信データ（§7）
- 送信プロンプトは `build_prompt` が組み立て、**指示文＋入力本文（`input_text`）のみ**。記事メタデータ・`context` は送信しない（単体テスト `build_prompt_includes_instruction_and_input_only` で `context` 非送信を担保）。
- 送信ボディは `generateContent` 形式の最小（`contents[].parts[].text` のみ）。
- Provider 切替時も最小化ルールは共通（mock/gemini）。
- 判定: ✅ §7.1 のAI送信最小化に準拠。

## 5. ログ出力（§12.2 / §12.3 / §19.1〜19.4）
- Rust 内の全 `log::*` 呼び出しをレビュー。出力内容は次に限られる:
  - ファイルI/Oの失敗・バックアップ復元（temp/bak/restore 系）
  - フィード/記事URLの**拒否・取得失敗**（URLは公開情報・診断目的）
  - モデルID検証の警告、`GEMINI_API_KEY is not set`（**キー値は出さず未設定の事実のみ**）
  - Gemini失敗時の `{error}`（reqwest エラー。キーはヘッダのみでURL/エラーに含まれない）
- **APIキー・本文全文・選択文字列全文・実ユーザーデータの出力は無し**。
- 判定: ✅ §12.3 準拠。
- 軽微: feed/記事URLの warn 出力は許容範囲。気になる場合は将来 debug レベルへ下げる選択肢あり。

## 6. 要対応: Content-Security-Policy（CSP）
### 現状
`src-tauri/tauri.conf.json` の `app.security.csp` が `null`（CSP未注入）。セキュリティ詳細設計書にCSPの明示規定は無いが、Tauri 公開/配布前の標準ハードニングとして制限的CSPの設定を推奨する。

### 提案値（要 `tauri dev` 検証）
webview は外部へ直接通信せず、取得は全て Rust 経由。よって `connect-src` に外部ホストは不要。styled-jsx/Tailwind のインラインスタイルのため `style-src 'unsafe-inline'` を許容する想定。

```text
default-src 'self';
img-src 'self' asset: data:;
style-src 'self' 'unsafe-inline';
script-src 'self';
connect-src 'self' ipc: http://ipc.localhost;
font-src 'self' data:;
object-src 'none';
base-uri 'self';
frame-ancestors 'none'
```

### 検証手順（後続PRで実施）
1. 上記を `app.security.csp` に設定。
2. `pnpm tauri dev` で起動し、各画面（Main/Reader/Dictionary/Settings/History/Onboarding 等）が描画されること、devtools コンソールに CSP 違反が出ないことを確認。
3. Next.js のインラインスクリプト等で `script-src 'self'` が不足する場合は、Tauri の nonce 機構の利用または許容ディレクティブの最小追加で調整。
4. 問題なければ確定。**未検証のまま `null` 以外へ変更して配布しない**（描画破壊の回避＝安全側）。

> 本点検PRではコード変更を行わず、上記を後続タスクとして起票する（webview 実機検証が必要なため）。
