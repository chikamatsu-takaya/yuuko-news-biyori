## 5. ログ出力（§12.2 / §12.3 / §19.1〜19.4）
- Rust 内の全 `log::*` 呼び出しをレビュー。出力内容は次に限られる:
  - ファイルI/Oの失敗・バックアップ復元（temp/bak/restore 系）
  - フィード/記事URLの**拒否・取得失敗**（URLは公開情報・診断目的）
  - モデルID検証の警告、`GEMINI_API_KEY is not set`（**キー値は出さず未設定の事実のみ**）
  - Gemini失敗時の `{error}`（reqwest エラー。キーはヘッダのみでURL/エラーに含まれない）
- **APIキー・本文全文・選択文字列全文・実ユーザーデータの出力は無し**。
- 判定: ✅ §12.3 準拠。
- 軽微: feed/記事URLの warn 出力は許容範囲。気になる場合は将来 debug レベルへ下げる選択肢あり。

## 6. Content-Security-Policy（CSP）
### 現状
`src-tauri/tauri.conf.json` の `app.security.csp` と `app.security.devCsp` はPR #65で設定済み。本番CSPには外部通信先を追加せず、WebViewからの外部通信をRust側の許可リスト境界へ限定している。2026-06-15にWindows/WebView2実機で描画・操作・違反ログを確認した。

2026-06-15に`pnpm exec tauri build --debug`が成功し、本番CSPを含むdebug実行ファイル・MSI・NSISを生成した。主要画面の表示と開発者ツール上のCSP違反確認も実施済みである。

初回目視ではCSP違反は確認されなかったが、Tauriでは提供されない`/_vercel/insights/script.js`をVercel Analyticsが要求し、HTML応答による構文エラーが発生した。デスクトップアプリでは不要な外部向けAnalyticsをRootLayoutと依存関係から削除し、再ビルド後のConsoleでCSP違反・構文エラーがないことを確認した。

### 適用値（Windows実機確認済み）
webview は外部へ直接通信せず、取得は全て Rust 経由。よって `connect-src` に外部ホストは不要。styled-jsx/Tailwind のインラインスタイルのため `style-src 'unsafe-inline'`、**Next.js static export が埋め込む RSC 用インラインスクリプトのため `script-src 'unsafe-inline'`** を許容する（static export は middleware 非対応で nonce を付与できないため）。

**適用値（本PR `chore/set-csp` で `app.security.csp` に設定済み）**:

```text
default-src 'self';
img-src 'self' data:;
style-src 'self' 'unsafe-inline';
script-src 'self' 'unsafe-inline';
connect-src 'self' ipc: http://ipc.localhost;
font-src 'self' data:;
object-src 'none';
base-uri 'self';
frame-ancestors 'none'
```

`null` からの主な強化点: `default-src 'self'`（既定で同一オリジン限定）/ 外部 `script`・`connect`・`object` の遮断 / `frame-ancestors 'none'`（クリックジャッキング防止）/ `base-uri 'self'`。`script-src` の `'unsafe-inline'` は static export の制約上残るが、本アプリは `dangerouslySetInnerHTML` 不使用・出力はReactエスケープのため HTML/スクリプト注入経路が無く、実リスクは小さい。

### 検証手順（要・実機／人による目視確認）
1. ✅ `app.security.csp`（本番）と `app.security.devCsp`（dev用・HMR/eval を許容した緩和版）を設定（本PR）。
   - Tauri は `devCsp` 未設定だと `csp` を dev にも適用するが、Next dev(Turbopack) の HMR(`ws://localhost:3000`)・eval が必要なため、dev では遮断され誤判定になる。よって dev 専用の緩和版（`'unsafe-eval'`・`ws`/`http://localhost:3000` を追加）を用意した。本番 `csp` はそれらを含まない（static export では不要）。
2. `pnpm exec tauri dev` で起動 → 開発者ツール（dev は常時有効）のコンソールで **CSP違反が無い**こと・全画面（Main/Reader/Dictionary/Settings/History/Customize/Gacha/Onboarding）が描画/操作できることを確認。
3. 本番CSPを厳密に確認する場合は `pnpm exec tauri build --debug`（devtools有効＋本番 `csp` 適用）でバンドルを起動して確認する。※ `--debug` 無しのリリースビルドは devtools 無効でコンソールが見られない。
4. 違反が出たディレクティブをコンソールで特定し、最小限で調整（不足する `connect-src`/`img-src` 等の追加）。**目視で描画OKを確認できるまで配布しない**（白画面＝ハイドレーション失敗の回避＝安全側）。
