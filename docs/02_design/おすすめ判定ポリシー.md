# おすすめ判定ポリシー（スコアリング・キーワード）

最終更新: 2026-06-10
対象: `RecommendationService` のおすすめスコア算出（重み・キーワード）の方針と初期値
根拠: データ設計書 §6 / 要件定義書 §7.4A・§14 / 詳細設計書 §5.3.2

## 1. 目的
- おすすめスコアの **算出モデル（要素・重み）** と **初期キーワード候補** を明文化する。
- 重み・キーワードの **管理場所** を定める。
- 社内ニュース等の **将来拡張を阻害しない** 方針を示す。

## 2. スコアモデル（現行実装）
記事1件のスコアは 0.0〜1.0。加点要素を合算し、既読ペナルティ係数を乗じてクランプする（`RecommendationService::calculate_score`）。純関数・単体テスト可能で、外部I/O・時刻取得を持たない。

| 要素 | 既定重み | 内容 | 判定関数 |
|---|---:|---|---|
| ジャンル一致 `genre_match` | 0.35 | 設定の選好ジャンルと記事ジャンルの一致（部分一致・大小無視） | `genre_matches` |
| 重要キーワード `keyword_match` | 0.30 | タイトル/タグに重要キーワードを含む | `has_important_keyword` |
| 驚き表現 `surprise` | 0.20 | タイトルに驚き語彙を含む | `contains_surprise_expression` |
| 鮮度 `freshness` | 0.15 | 取得からの経過時間で線形減衰（窓 72時間） | `freshness_factor` |
| 既読ペナルティ | ×係数 | 未読1.0 / プレビュー済0.85 / 詳細閲覧0.6 を全体に乗算 | `read_state_multiplier` |

加点要素の最大合計は 1.0（正規化済み）。

### 2.1 データ設計書 §6.1 との対応
設計書の6要素比率（importance30 / surprise20 / categoryMatch20 / userTrendMatch10 / freshness8 / readPenalty-6）を、MVP実装では4加点＋ペナルティ係数へ簡約している。

| データ設計書 §6.1 | 実装 |
|---|---|
| categoryMatch | `genre_match`（0.35） |
| importance ＋ userTrendMatch | `keyword_match`（0.30。重要/関心キーワードで近似） |
| surprise | `surprise`（0.20） |
| freshness | `freshness`（0.15） |
| readPenalty | `read_state_multiplier`（乗算係数） |

## 3. 初期キーワード候補（MVP）
MVPの検証ソースは Publickey（テクノロジー）。初期の **重要キーワード** は AI/IT 領域の注目語を中心にする（`RecommendationService::INITIAL_IMPORTANT_KEYWORDS`）。

- 生成AI / LLM / 大規模言語モデル / オープンソース / セキュリティ / 脆弱性 / クラウド / 量子 / 規制 / 標準化

**驚き表現キーワード**（`SURPRISE_TERMS`）: 最大 / 最高 / 過去最高 / 世界初 / 国内初 / 急増 / 急減 / 記録的 / 初めて / 驚異。

いずれも **ヒューリスティックな初期値** であり、運用しながら調整する（語彙の過不足はタイトル誤マッチに直結するため、追加は慎重に）。

## 4. 重み・キーワードの管理方針
- **MVP**: 重み（`RecommendationWeights::default`）・驚き語彙（`SURPRISE_TERMS`）・重要キーワード（`INITIAL_IMPORTANT_KEYWORDS`）は **Rust 側の定数** として管理し、本ドキュメントを正とする。変更はコードレビューを通す。
- 選好ジャンル（`preferred_genres`）は **ユーザー設定**（`settings.news.categories`）由来で、`NewsService` が採点コンテキストへ供給する。
- **将来**: 重要キーワードは「ユーザー傾向メモ」（要件 §7.4A.5）由来へ拡張、重みの設定化（設定画面 / 設定JSON）も候補。設定化する場合も **最小化・既定値はコード保持** を維持する。

## 5. 将来拡張（社内ニュース等）を阻害しない方針
- スコアモデルは **ジャンル / キーワード / 鮮度 / 既読** という汎用属性に基づき、特定媒体や外部URL前提を持たない。よって社内ニュース・お知らせも同じ枠組みで採点できる（要件 §14 / §11.0）。
- 社内ソースを混在させる場合も、`genre` と `important_keywords` の設計だけで対応でき、スコア算出ロジックの変更は不要。
