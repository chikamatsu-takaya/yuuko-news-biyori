# ゆうこ着せかえ 素材受け入れ基準

ゆうこの着せかえ（吹き出し・飾り〔アクセサリー〕。判断台帳 D155）の素材を足す・差し替えるときの条件と手順。
仕組み・保存の扱いは「データ設計書」§11.2 / §12.4、画面での見せ方は「画面詳細設計書」SCR カスタマイズ画面を参照する。
模様の素材は「テーマ模様_素材受け入れ基準.md」。

## 1. 前提（決定事項）

- 吹き出し10種・飾り10種。最初から使えるのは吹き出し「いつもの」と飾り「なし」だけで、既定もこの2つ（新規・既存ユーザーとも今の見た目を変えない）。
- 残り19種はガチャの種類「吹き出し」「飾り」で手に入れる（未所持から等確率で1つ。かけらの量・コストは変えない）。
- 季節もの（桜・サンタ帽）も自動では切り替えず、ふつうのガチャ品として扱う。
- 字体は足さない。見本でドット風の字体（DotGothic16）を使っていた「ドット絵」「ゲームの窓」の吹き出しも、アプリの普通の字体で出す。

## 2. 吹き出し

| 項目 | 基準 |
|---|---|
| 描き方 | 画像は使わず CSS だけで描く（`app/globals.css` の `.yuuko-bb-<形の英語名>`、`@layer components`）。外部の画像・字体を読まない |
| 色 | 各テーマの CSS 変数から取る（ふち・アクセントは `--yuuko-green-text`、淡い地は `--yuuko-green-light`、細い線は `--border`、文字は `--foreground`）。1つの CSS で全 6 テーマに合う。固定色は白・黒（ドット絵のふち `#1a1a1a`）・エアメールの赤など、テーマに依らない飾りの色だけにする |
| 本文の地 | 白（`#fff`）か、テーマの淡い色（`--yuuko-green-light`）。濃い地にするのは「ゲームの窓」だけで、文字は白にする |
| 読みやすさ | 本文の文字と地の対比は全 6 テーマで WCAG AA（4.5:1）以上。罫線・しま模様などの飾りは文字の下に濃く重ねない（ノートの罫線は `--border` の細線） |
| しっぽ | ゆうこのいる側へ向ける。`data-tail` の `bottom-left`（基本）/ `bottom-right` / `right` / `none` を、その形で描けるようにする（しっぽの無い形は付箋・エアメール） |
| 置き方 | 画面ごとの幅・外側の余白・閉じるボタン分の右余白は使う側の Tailwind で上書きできるようにする（形の側に `!important` を使わない）。影・ふち・角丸・地の色は形の側が持つ |
| 動き | 動きを付けるなら `prefers-reduced-motion: no-preference` の中でだけ付ける（ゲームの窓の ▼ の点滅は、動きを抑える設定では止まって表示される） |
| ハイコントラスト | Windows ハイコントラスト（`forced-colors`）では影・背景で描いたふちが消えるため、OS の文字色で輪郭を足す |
| 「いつもの」 | 新しい形を作らず、各画面がもともと持つ吹き出しの形（白の角丸・淡いふち・各画面のしっぽ）をそのまま使う（`components/yuuko/YuukoBalloon.tsx` の `defaultClassName` / `defaultTail`） |

## 3. 飾り（アクセサリー）

| 項目 | 基準 |
|---|---|
| 形式 | SVG ファイル（`public/assets/accessories/<物の英語名>.svg`）。アプリに同梱し、外部から読み込まない（CSP は `img-src 'self' data:`） |
| 座標系 | 立ち絵 `public/assets/yuuko.png`（639×779）と同じ座標で描く。`viewBox="0 -100 639 879"`・`width="639" height="879"` に固定し、立ち絵の上に同じ縮尺で重ねる（立ち絵の下端にそろえる） |
| 描き方 | ゆうこと同じ黒ふち（`#1a1a1a`）のドット絵。`<rect>` の四角だけで描き、`shape-rendering="crispEdges"` を付ける（拡大・縮小でもにじませない）。グラデーション・ぼかし・影・`<image>`・`<text>`・`<script>`・外部参照は使わない |
| 隠さないもの | ゆうこのフード・首輪のメダル・おなかの「S」・しっぽを隠さない位置に置く |
| 目の上のもの | 黒い顔に重なる飾り（サングラス・メガネ）は、しっかり色を付け、ふちも黒い顔に溶けない色にする（例: 丸サングラスは白ぶち、ぐるぐるメガネは灰色ぶち、ハートは濃いピンクのレンズ）。目の高さ（y 150〜290）にかかる飾りは明るい色（相対輝度 0.3 以上）を必ず含む |
| はみ出し | 立ち絵の左右・下へははみ出さない。上（頭に乗せるもの）へは最大 100 まで（`y >= -100`）。はみ出す高さは `lib/yuuko-dressup.mjs` の `overTop` に書き、表示側はその分だけ上に余白を取る（外側の `overflow` で切れないように） |
| 容量 | 1ファイル 32KB 未満を目安にする（現状は最大でもぐるぐるメガネの約 23KB） |
| 小さい表示 | 常駐ゆうこウィンドウ大（立ち絵の幅 66px 程度）でも形が分かること。細かすぎる模様（1〜2 マスの点の集まり）は避ける |

## 4. 避けるもの

- キャラクター IP・ブランドを思わせる形や柄。
- フリー素材のトレース・既存作品の模写。形は自分たちで単純な図形から組み立てる。
- 顔の表情を変えて見えるもの（表情差分はガチャの対象外）。
- 字体の追加（同梱すると容量・ライセンスの確認が増えるため。D155）。

## 5. 追加・差し替えの手順

1. 吹き出しなら `app/globals.css` に `.yuuko-bb-<形>` を足す（しっぽの向き `data-tail` も）。飾りなら SVG を `public/assets/accessories/` に置く。
2. `lib/yuuko-dressup.mjs` の `UI_BALLOONS`（`id` / `label` / `note` / `shape`）または `UI_DECOS`（`id` / `label` / `note` / `file` / `overTop`）に 1 件足す。
3. `src-tauri/src/domain/gacha.rs` の `GACHA_MASTER` に `balloon("<id>", "<表示名>")` / `deco("<id>", "<表示名>")` を足す（ID は `gacha_balloon_<形の英語名>` / `gacha_deco_<物の英語名>`）。
4. ガチャの総数を数えている Rust のテスト・データ設計書 §12.4・要件定義書 §7.6B.4 の数を更新する。
5. `node --test lib/yuuko-dressup.test.mjs` で、ID・表示名が CSS と Rust に揃っていること、吹き出しの本文の対比（全テーマ AA 以上）、飾りが本基準（座標系・四角だけ・外部参照なし・はみ出し・容量）を満たすことを確かめる。全 6 テーマ・主な画面（辞書・ニュース閲覧・設定・履歴・カスタマイズ・ガチャ）で見た目を確認する。

一度出した ID は保存データ（`ownedItemIds`・`ui.balloonId` / `ui.decoId`）に残るため、表示名や形を直しても ID は変えない。廃止する場合も、ID を別の品に使い回さない。
