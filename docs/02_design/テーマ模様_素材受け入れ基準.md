# テーマ模様 素材受け入れ基準

テーマの「地」に薄く敷く模様（判断台帳 D152〜D154）の素材を足す・差し替えるときの条件と手順。
模様の仕組み・保存の扱いは「データ設計書」§11.2 / §12.4、画面での見せ方は「画面詳細設計書」SCR カスタマイズ画面を参照する。

## 1. 前提（決定事項）

- 模様は色テーマとは独立に選ぶ（色テーマ × 模様）。既定は新規・既存ユーザーとも「なし」（今の見た目を変えない）。
- 最初から使えるのは「なし・水玉・肉球」。残りはガチャの種類「模様」で手に入れる（未所持から等確率で1つ。かけらの量・コストは変えない）。
- 季節の自動切り替えはしない。季節の柄もふつうのガチャ模様として扱う。
- 濃さ・大きさは模様ごとの推奨値で固定し、利用者が調整する UI は置かない。

## 2. 形式

| 項目 | 基準 |
|---|---|
| 形式 | 単色の SVG ファイル（`public/assets/patterns/<形の英語名>.svg`）。アプリに同梱し、外部から読み込まない（CSP は `img-src 'self' data:`） |
| 描き方 | 形を黒（`#000`。fill を省略した既定の黒でもよい）で描く。CSS の `mask-image` で型抜きに使い、色は各テーマの文字色 `--yuuko-green-text` で塗るため、1つの SVG で全テーマに合う。重なりを抜くための SVG 内 `<mask>`（白 `#fff`）は使ってよい（例: 青海波） |
| 使わないもの | 色・グラデーション・ぼかし・影・写真・ノイズ（粒状感）・`<image>`・`<text>`・`<script>`・外部参照（`href` / 外部 `url()`）。型抜きでは色が捨てられ、グラデーションやノイズは汚れに見えるため |
| 寸法 | `width` / `height` / `viewBox` を実寸 px で書く。実際のタイル（実寸 × 大きさ）が縦横とも 24〜72px に収まること（調査の目安は 32〜64px）。継ぎ目が出ないよう、タイルの端で形が途切れても反対側とつながるように描く |
| 容量 | 1ファイル 4KB 未満を目安にする（現状は最大でも青海波の約 3.7KB） |
| モチーフの量 | 1タイルのモチーフは 2〜3 種まで。塗り面積はタイルの 20% 以下を目安にし、面の大きい柄（ギンガム・太ストライプなど）は濃さを下げて釣り合わせる |

## 3. 濃さ・大きさ

- 濃さ（`opacity`）は、各テーマの地の色に文字色を重ねたときのコントラスト比が 1.15〜1.30 になる範囲を目安にする。6 テーマとも、濃さ 11% で 1.15、19% で 1.30 相当（調査メモ 2026-10-20）。
- 細い線の柄はこの範囲の濃いめ（方眼 16%・雪 16%・青海波 15%）、面の大きい柄は範囲より薄くしてよい（マルシェストライプ 6%）。19% は超えない。
- 大きさ 100% = SVG の実寸。100% 以外にするときも、CSS では整数 px に丸める（`mask-size` が小数だとタイルの継ぎ目に線が出ることがあるため）。
- 推奨値は比較ページで藤井さんが確認した値（`lib/ui-pattern.mjs` の `UI_PATTERNS` と、データ設計書 §12.4 の表）。

## 4. 避けるもの

調査（2026-10-20。LINE 着せかえの傾向、Pinterest Predicts 2025・2026、Pantone / WGSN 2026 などの公開情報）と比較ページでの評価から、次は採らない。

- 顔のある記号の繰り返し（例: ゆうこの顔のドット。抽象的すぎて謎の生き物に見えたため不採用）。ゆうこ本人は立ち絵に任せ、背景は肉球・骨など「犬にまつわる記号」で補う。
- キャラクター IP を思わせるシルエット。
- ブランドを思わせるチェック（バーバリー風のチェック、ベージュ地に黒と赤のタータン、茶色 2 色の市松〔ダミエを思わせる〕）。
- フリー素材のトレース・既存作品の模写。形は自分たちで単純な図形から組み立てる。
- 新聞・メガホンなど、ニュースそのままのアイコン（フリー素材っぽく見えるため不採用）。
- 詰め込み・原色・影。

## 5. 敷き方の決まり

- 文字の下には敷かない。模様はメインウィンドウの地（サイドバー・タイトルバー・フッターを除く部分）にだけ出し、本文・カード・吹き出しは不透明な白の上に置く。
- 画面全体に1枚の層として敷く（`components/layout/PatternGround.tsx`・ビューポート基準）。列ごとに別の層にすると、境目で柄の並びがやり直しになり段差ができる。
- 層は操作を受けない（`pointer-events: none`）・読み上げない。印刷と Windows ハイコントラスト（`forced-colors`）では消す。
- 常駐ゆうこウィンドウには敷かない。

## 6. 追加・差し替えの手順

1. SVG を `public/assets/patterns/` に置く（ファイル名は形の英語名）。
2. `lib/ui-pattern.mjs` の `UI_PATTERNS` に 1 件足す（`id` / `label` / `file` / 実寸 / 濃さ / 大きさ）。
3. `app/globals.css` に同じ ID の `[data-pattern="<id>"]` ブロックを足す（素材 URL・`mask-size`・濃さ）。
4. ガチャで出す模様なら、`src-tauri/src/domain/gacha.rs` の `GACHA_MASTER` に `pattern("<id>", "<表示名>")` を足す（ID は `gacha_pattern_<形の英語名>`）。最初から使える模様にするなら `src-tauri/src/domain/pattern.rs` の `INITIAL_PATTERN_IDS` に足す（ID は `pattern_<形の英語名>`）。
5. ガチャの総数を数えている Rust のテスト・データ設計書 §12.4・要件定義書 §7.6B.4 の数を更新する。
6. `node --test lib/ui-pattern.test.mjs` で、ID・表示名・推奨値が CSS と Rust に揃っていること、素材が本基準（単色・寸法・外部参照なし・濃さ 19% 以下・容量）を満たすことを確かめる。比較用に全 6 テーマで見た目を確認する。

一度出した ID は保存データ（`ownedItemIds`・`ui.patternId`）に残るため、表示名や形を直しても ID は変えない。素材を廃止する場合も、ID を別の模様に使い回さない。
