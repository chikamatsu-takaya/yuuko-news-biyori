# PRマージ後の Firestoreタスク状態判定ルール

## このドキュメントの目的
- 将来的に、**PR マージ後に Firestore タスクを `Done` または `Review` に更新**し、その結果を `docs/00_project/developタスクチェックリスト.md` へ反映できるようにするための **状態判定ルールを明文化** する。
- マージ後に「そのタスクを自動で Done にしてよいか / Review に留めるべきか / 触らないべきか」の判断基準を、人間と AI が同じ前提で扱えるようにする。
- 本ドキュメントは **判定ルールの定義のみ** を扱う。実装（GitHub API 連携・GitHub Actions・Firestore 自動更新・md 自動更新）は含まない。

> 関連: PR と Firestore タスクの紐づけ方針は `docs/00_project/firestore-task-pr-linking-rule.md` を参照。本ドキュメントは、その紐づけで対象タスクが特定できた前提で「マージ後にどの状態へ寄せるか」を定義する。

---

## 現時点の方針（重要）
- **現時点では自動更新を実装しない。**
- PR マージを検知して Firestore タスクを書き換える処理、および `developタスクチェックリスト.md` を自動更新する処理は、本ドキュメントの段階では作らない。
- まずは判定ルールを固め、当面は **人間が本ルールを参照して手動で状態遷移** させる。
- したがって、`Doing → Done` / `Doing → Review` / `Review → Done` の遷移は、これまでどおり進捗管理画面の手動ボタンで行う。

---

## 前提: 「マージ済み」が意味すること・意味しないこと
- PR がマージ済みであることは、**AI レビューゲートを通過した**ことを意味する。
- ただし、マージ済みは以下の完了を **意味しない**。
  - 目視確認（実際の画面・出力を人間が見て確認すること）
  - 動作確認（実際に動かして期待どおりか確かめること）
  - 仕様判断（要件・意図に照らして妥当かの最終判断）
- したがって、「マージ済み = 無条件で Done」とはしない。**変更の性質に応じて Done 候補 / Review 候補を判定** する。

---

## マージ後の状態判定

### Done 候補にしてよい条件
以下のように、**目視確認・動作確認・仕様判断が不要と明確に言える軽微な変更**のみで構成される PR は、`Done` 候補としてよい。

- ドキュメント（docs）のみの変更
- PR テンプレートのみの変更
- README や設定手順の説明追加のみ
- コメントや文言のみの変更
- 動作確認が不要な軽微変更

補足:
- 上記に該当しても、後述の「Review 候補」条件や「更新しない条件」に一つでも当たる場合は、そちらを優先する（安全側に倒す）。

### Review 候補にすべき条件
以下のいずれかに該当する PR は、目視・動作・仕様のいずれかの確認が必要とみなし、`Review` 候補とする。

- UI 変更あり
- Firestore 読み書きの変更あり
- 状態遷移ロジックの変更あり
- Tauri command の変更あり
- Rust 側実装あり
- 外部通信先の変更あり
- セキュリティ関連の変更あり
- 複数タスクを含む PR
- PR 本文の確認項目が不足している
- 動作確認結果が不明

### 自動判定できない場合
- 変更内容から Done / Review を **自動で判定できない場合は、`Review` とするか、状態を変更しない**（安全側）。
- 「判断に迷うなら Done にしない」を原則とする。誤って Done 化するより、Review または現状維持のまま人間の確認に回す方を優先する。

---

## Firestoreタスクを更新しない条件
以下のいずれかに該当する場合は、`Done` / `Review` いずれの候補判定も行わず、**対象 Firestore タスクを更新しない**。

- 対象タスクを特定できない
- `branchName` / `taskCode` / `issuePr` が不一致（紐づけが確定しない）
- 対象タスクがすでに `Done`
- `archived === true`
- PR が `develop` 向けではない
- PR がマージ済みではない

補足:
- ここでの `branchName` は Firestore 上の正本 `task.branchName` を指す（`docs/00_project/firestore-task-pr-linking-rule.md` の「正本の明確化」に準拠）。
- 更新しないと判断した場合は、状態を書き換えず、必要に応じて人間の手動確認に委ねる。

---

## 既存の手動遷移ボタンとの関係
本ルールは、進捗管理画面（`task-management/`）の既存手動遷移と **同じ状態遷移の考え方**を、マージ後判定として整理したものである。将来自動化する場合も、これらの手動ボタンが通す安全条件（transaction による現状確認など）を迂回しないことを前提とする。

| 手動ボタン | 対応する本ルールの考え方 |
|---|---|
| `Doing → Done`（問題なしでDone） | マージ後に **Done 候補** と判定できる軽微変更に相当。動作確認・目視・仕様判断が不要なケース。 |
| `Doing → Review`（レビューに回す） | マージ後に **Review 候補** と判定すべきケース。目視・動作・仕様のいずれかの確認が必要。 |
| `Review → Done`（レビュー完了） | Review 候補として確認に回した後、**人間の確認完了をもって Done** にする段階。マージ後自動判定だけでこの遷移を代替しない。 |

- 自動判定はあくまで「Done 候補 / Review 候補 / 更新しない」の**候補提示まで**を想定し、最終的な `Review → Done` は人間の確認を経る前提とする。

## developタスクチェックリストへの反映について（前段ルール）
- 本ドキュメントは、将来的に **Firestore の状態を `docs/00_project/developタスクチェックリスト.md` に反映するための前段ルール** である。
- 流れの想定（いずれも将来実装）:
  1. PR マージを検知する。
  2. 本ルールで対象 Firestore タスクの状態候補（Done / Review / 更新しない）を判定する。
  3. Firestore タスクを更新する（自動更新を有効化した場合）。
  4. その結果を `developタスクチェックリスト.md` に反映する。
- 現段階では 1〜4 のいずれも自動実装しない。本ドキュメントは 2 の判定基準を先に固めることを目的とする。
- `developタスクチェックリスト.md` への反映を自動化する前に、まず Firestore 側の状態判定が安定して正しく行えることを確認する。
