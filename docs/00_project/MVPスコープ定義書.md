# MVPスコープ定義書 v1

## 1. 文書目的
本書は、AIニュースマスコットアプリ「ゆうこのニュース日和」の初期開発・社内発表に向けて、最小実用版（MVP: Minimum Viable Product）の範囲をTauri版の実装前提で定義するものである。

本プロジェクトは、ニュース取得、AI要約、用語解説、マスコット「ゆうこ」、友情ランク、テーマ・デコ、ガチャ、データ移行など多くの要素を持つ。  
ただし、初期開発ですべてを実装対象にすると、開発負荷が高くなり、発表時に中核価値が伝わりにくくなる恐れがある。

そのため本書では、以下を明確にする。

- MVPで必ず作るもの
- MVPでは簡易実装に留めるもの
- MVPでは対象外にするもの
- 発表時に見せるべき体験
- 後続開発へ回す要素
- Tauri / React / TypeScript / Rust における実装優先範囲

---

## 2. 技術前提

### 2.1 MVPでの採用技術
Tauri版MVPでは、以下の技術構成を前提とする。

| 領域 | 技術 | MVPでの役割 |
|---|---|---|
| デスクトップアプリ基盤 | Tauri v2 | アプリ起動、WebView、Rust連携 |
| UI | React | 画面、ゆうこ表示、モーダル、ポップアップ |
| UI言語 | TypeScript | 型安全な画面実装、Tauri command呼び出し |
| 中核ロジック | Rust | ニュース取得、保存、AI連携、辞書、ランク管理 |
| ビルド | Next.js / pnpm | フロントエンド開発、Tauri起動 |
| 保存 | Markdown / JSON | ローカルニュース、設定、辞書、状態保存 |
| AI | Gemini API / MockProvider | 要約、再説明、用語解説 |
| エディタ | VS Code | 開発、拡張機能、AI駆動開発 |

### 2.2 C++ / Qt / QMLの扱い
MVP段階では、C++ / Qt / QMLを使用しない。

旧C++ / Qt版資料は別案として残すが、Tauri版MVPでは以下を基本とする。

```text
React / TypeScript = UIとユーザー操作
Rust = 業務ロジック、保存、通信、AI連携
Tauri command = ReactとRustの接続口
```

### 2.3 MVPの起動確認基準
MVP開発では、最低限以下が通る状態を維持する。

```bash
pnpm tauri dev
```

必要に応じて以下も確認する。

```bash
pnpm dev
cd src-tauri
cargo check
```

## 3. MVPの基本方針

### 3.1 MVPの目的
MVPでは、以下の体験を最優先で成立させる。

> ゆうこがニュースを届け、AI要約と用語解説によって、ユーザーがニュースを読みやすくなる。

初期版で最も大事なのは、以下の3点である。

1. ニュースが取れる
2. AIで分かりやすく要約・解説できる
3. ゆうこが案内役として自然に関わる

### 3.2 MVPで重視すること
- 実用性が伝わること
- ゆうこが単なる飾りではなく、体験の中心にいること
- 軽量常駐アプリとしての方向性が見えること
- AI駆動開発の成果物として説明しやすいこと
- 発表時にデモしやすいこと
- 今後拡張できる余地があること
- Tauri / React / Rustの責務分離が崩れないこと
- APIキーなしでもMockProviderでデモできること

### 3.3 MVPで重視しないこと
- 報酬やガチャ要素の完全実装
- 大量のテーマやデコレーション
- 高度なアーカイブ検索
- Google Driveデータ移行の本実装
- Googleメール連携
- 完璧なニュース媒体別HTML抽出
- Live2D等の高度なキャラクター演出
- 複数AI Providerの正式対応
- OSレベルの高度な通知抑制

## 4. MVPで見せたい利用シナリオ

### 4.1 基本デモシナリオ
MVP発表では、以下の流れを見せられることを目標とする。

```text
1. Tauriアプリを起動する
2. 起動時にニュースを取得する
3. ゆうこが画面端から出てきてニュースを紹介する
4. ゆうこをクリックすると簡易プレビューが出る
5. さらにクリックするとメイン画面またはニュース閲覧画面へ遷移する
6. ニュースのAI要約・再説明・注目ポイントが表示される
7. 気になる用語を選択する
8. 用語解説ボタンを押す
9. ゆうこが短く解説する
10. 解説内容がゆうこ辞書に保存される
```

MVP必須の通しデモはニュース取得〜辞書保存（手順1〜10）まで。友情ポイント・ランク進捗・ランクアップ表示は実装済みだが、MVP必須の完了条件・必須通しデモには含めない。

#### 追加機能の任意デモ

次は実装済みだが、MVP必須の通しデモ・完了条件には含めない（任意）。

| ID | 操作 | 確認内容 |
|---|---|---|
| A1 | 友情ポイント増加 | ニュース閲覧・用語解説でポイントが増える |
| A2 | ランク進捗確認 | 簡易的なランク進捗を確認できる |

### 4.2 MVPで伝えたい価値
- タイトルだけでは分かりにくいニュースを、ゆうこが読みやすくしてくれる
- 難しい単語をその場で噛み砕いてくれる
- 使うほど辞書やランクが育つ
- 業務中でも邪魔にならないよう、軽い常駐体験を目指している
- ローカル保存中心なので、大きな運用コストをかけずに始められる
- AIが使えない状態でもMockProviderで画面と体験を確認できる

## 5. MVP対象範囲

---

### 5.1 ニュース取得機能

#### MVP範囲
- RSSからニュース候補を取得する
- 初期カテゴリはIT / AIを中心とする
- 起動時に1回取得する
- 取得したニュースをローカル保存する
- 重複ニュースを簡易判定する
- 取得処理はRust側で行う
- React側は取得結果の表示と更新操作のみ担当する

#### MVPでの簡略化
- 日付変更時の自動更新は実装候補だが、最初は手動実行または起動時のみでも可
- 媒体別の高度なHTML抽出は不要
- RSS本文や概要が取れない場合は、タイトル・出典・URL中心で扱う
- 許可ドメイン管理は簡易JSONまたは固定配列でも可

#### 完了条件
- 起動時にニュース一覧を作成できる
- 最低限、タイトル・出典・URL・取得日時・ジャンルを保存できる
- 同一URLの重複を避けられる
- React側にRSS取得処理を書いていない

---

### 5.2 ニュース保存機能

#### MVP範囲
- 1記事1Markdown相当で保存する
- ニュースID、タイトル、出典、URL、取得日時、ジャンル、要約、表示状態を保持する
- ローカル保存を基本とする
- 保存処理はRust側repositoryで行う
- React側はTauri command経由で保存済みニュースを受け取る

#### MVPでの簡略化
- 完全な月次アーカイブ圧縮は後回しでも可
- お気に入り記事の専用フォルダ移動は簡易フラグ管理でも可
- Markdown Front Matterの最終仕様は後続で微調整してよい

#### 完了条件
- 再起動後も取得済みニュースを参照できる
- 保存データが人間にも読める形式で残る
- React側から任意パスを指定してファイル保存していない

---

### 5.3 AI要約機能

#### MVP範囲
- Gemini API Free Tierを用いた要約生成
- MockProviderによる固定応答切替
- ニュース本文抜粋または概要を入力にして、1〜3文程度の要約を生成する
- ゆうこの一言または短い紹介文を生成する
- AI呼び出しはRust側で行う
- APIキーはReact側へ渡さない

#### MVPでの簡略化
- 高度なモデル切替UIは不要
- OpenAI API対応は後回し
- 長文全文投入は行わず、入力は短く制限する
- プロンプト管理は初期段階では簡易テンプレートでも可

#### 完了条件
- ニュースごとにAI要約が表示できる
- Gemini APIが使えない場合でもMockProviderで画面確認できる
- AI送信対象データが最小限に抑えられている
- APIキーがGit、React state、ログに出ていない

---

### 5.4 メイン画面

#### MVP範囲
- 今日のおすすめニュース一覧を表示する
- ゆうこを画面中央下寄りに配置する
- 未読数などの状態表示枠を用意する（ランク進捗・流れ星のかけら数など育成系の表示枠は追加機能・任意）
- ニュース閲覧画面、設定画面、辞書画面への導線を用意する
- React / TypeScriptで実装する
- データ取得はTauri command経由とする

#### MVPでの簡略化
- 実際のかけら加算やガチャ連携はダミー表示でも可
- ゆうこの自由移動は簡易アニメーションまたは固定配置でも可
- 全画面テーマ切替は後回し

#### 完了条件
- メイン画面から主要画面へ遷移できる
- ゆうこがアプリ体験の中心にいることが視覚的に伝わる
- 仮データまたは保存済みデータで画面表示できる

---

### 5.5 ニュース閲覧画面

#### MVP範囲
- 記事タイトル、出典、URL、ジャンル、要約を表示する
- ゆうこの再説明文または紹介文を表示する
- 要点整理、注目ポイント欄を用意する
- 元記事リンクを表示する
- お気に入りボタンを用意する
- 選択語句から用語解説へつなげる
- React側では表示と操作受付を担当する
- 記事詳細取得、お気に入り更新、既読更新はTauri command経由で行う

#### MVPでの簡略化
- 関連ニュース表示は不要
- 前後記事移動は任意
- 元記事本文そのものの大量表示は行わない
- Markdownレンダラーを使う場合も危険HTMLは無効化する

#### 完了条件
- ニュースをアプリ内で読みやすく確認できる
- 原文リンクへ遷移できる
- ゆうこがニュース内容を説明している体験が伝わる
- HTMLを生表示していない

---

### 5.6 用語解説機能

#### MVP範囲
- ニュース閲覧画面上で文字列を選択できる
- 選択後に解説ボタンを表示する
- Gemini APIまたはMockProviderで短い解説を表示する
- 解説はゆうこの口調を想定した文体にする
- 解説結果をゆうこ辞書に保存する
- 選択文字列の検証とAI呼び出しはRust側で行う
- React側は選択UI、ボタン、ポップアップ表示を担当する

#### MVPでの簡略化
- 長文要点説明モードは簡易対応または後回しでも可
- 「もっと見る」はダミーまたは簡易表示でも可
- 解説レベル切替は設定値だけ先に用意し、実際の差分は最小限でも可
- 完全一致再利用は土台だけでも可

#### 完了条件
- 選択語句に対して解説が表示される
- 同じ語句を再度解説する際に辞書再利用の土台がある
- 選択文字列全文をログに出していない

---

### 5.7 ゆうこ辞書機能

#### MVP範囲
- 解説済み単語やフレーズを一覧表示する
- 辞書項目の詳細を表示する
- ★マークを付けられる
- 簡易メモ欄を持つ
- 不要項目を削除できる
- 辞書の保存・更新・削除はRust側で行う
- React側は一覧、詳細、検索、編集UIを担当する

#### MVPでの簡略化
- 類似検索は不要
- 高度な全文検索は不要
- 関連ニュース表示はIDまたはタイトル程度で可
- JSON配列または1項目1Markdownのどちらかで開始してよい

#### 完了条件
- 解説した内容を後から見返せる
- 完全一致再利用の下地がある
- 削除時に確認を挟める

---

### 5.8 ゆうこ通知・軽量プレビュー

#### MVP範囲
- ゆうこが画面端から出てくる簡易演出を用意する
- 短い吹き出しを表示する
- 初回クリックでニュース軽量プレビューを表示する
- 再クリックでメイン画面またはニュース閲覧画面へ遷移する
- 登場条件や通知回数はRust側で管理する
- 表示・アニメーション・クリック操作はReact側で行う

#### MVPでの簡略化
- 会議中判定、マイク使用中判定、フルスクリーン判定は後回しでも可
- 出現タイミングは手動トリガーまたはデモ用ボタンでも可
- 自由移動は簡易アニメーションで可
- 常駐ゆうこ専用小型Tauriウィンドウ方式は後続検証でも可

#### 完了条件
- 「ゆうこがニュースを持ってくる」体験をデモできる
- 閉じる、無視、詳しく見るの操作結果をRust側へ通知できる
- 通知が連打で多重発火しない

---

### 5.10 設定画面

#### MVP範囲
- 関心ジャンル設定
- 通知ON/OFF
- 解説レベル設定
- テーマ設定の枠
- Gemini API利用設定または環境変数利用案内
- MockProvider切替
- 設定保存はRust側で行う
- React側はフォーム表示と操作受付を担当する

#### MVPでの簡略化
- 抑制対象ソフト指定は後回し
- 自動起動設定は後回し
- Google連携設定は後回し
- 詳細セキュリティ表示は説明文程度で可
- APIキー入力UIはMVPでは必須にしない。環境変数利用でもよい

#### 完了条件
- 最低限のユーザー設定が保存される
- AI接続の開発・デモ切替ができる
- APIキーそのものを画面に表示しない

## 6. MVPでは簡易実装に留めるもの

### 6.1 お気に入り機能
#### MVP方針
- お気に入りボタンとフラグ保存のみ実装
- 専用画面や専用フォルダ移動は後続対応でも可
- 更新処理はRust側で行う

### 6.2 ニュース履歴画面
#### MVP方針
- 取得済みニュース一覧として簡易表示
- 既読・未読・お気に入りフィルタは最低限で可
- アーカイブ展開は後回しでも可

### 6.3 カスタマイズ画面
#### MVP方針
- 画面枠とプレビューのみ作る
- 実際のデコ・テーマ大量切替は後回し
- 1〜2個のテーマ切替だけでも可

### 6.4 ガチャ画面
#### MVP方針
- 発表映えを狙う場合は簡易デモ版を作る
- 流れ星のかけら数、ガチャボタン、結果モーダルのみでも可
- 排出率、重複処理、レアリティ詳細は後回し
- 抽選確定処理を作る場合はRust側に置く

### 6.5 アーカイブ機能
#### MVP方針
- 実際の月次圧縮は後回しでも可
- 画面またはデータ構造上の余地だけ残す
- ZIP化や展開は後続でRust側に実装する

## 7. MVP対象外

以下はMVPでは原則対象外とする。

### 7.1 Google Driveデータ移行
- ローカルZIP書き出しやDrive一時保存方式は重要な拡張候補だが、MVPでは対象外
- 設計資料として残すのみ
- 会社セキュリティ方針確認後に採用判断する
- 実装する場合はRust側または承認済み連携層でZIP化・暗号化・Drive連携を行う

### 7.2 Googleメール連携
- 重要メール通知補助は拡張候補
- MVPでは対象外
- メール情報をAIに送らない方針のみ資料として残す

### 7.3 高度な通知抑制
- 会議ソフト検知
- マイク使用中検知
- フルスクリーン検知
- 特定ソフト起動中判定

これらは重要だが環境依存が強いためMVPでは後回しとする。

### 7.4 本格的なガチャシステム
- 排出率管理
- レアリティ詳細
- 重複時還元
- 排出履歴管理
- 大量アイテム管理

MVPではデモ用の簡易体験に留める。

### 7.5 Live2D等の高度キャラクター制御
- 初期版では静止画、簡易アニメーション、差分表示でよい
- 高度なLive2D制御は後続検討とする

### 7.6 OpenAI API等の複数AI正式対応
- MVPではGemini API + MockProviderを中心とする
- OpenAI APIやローカルモデルは将来候補

## 14. MVPの完了判定

MVPは、以下を満たした時点で完了とみなす。

### 14.1 必須完了条件
- `pnpm tauri dev` でアプリが起動できる
- RSSからニュースを取得できる
- ニュースをローカル保存できる
- メイン画面にニュース一覧を表示できる
- ニュース閲覧画面でAI要約を表示できる
- ゆうこがニュース紹介役として画面に表示される
- 用語選択から解説を表示できる
- 解説結果をゆうこ辞書に保存できる
- 保存した用語をゆうこ辞書画面で確認できる
- アプリを再起動した後も、保存した用語がゆうこ辞書に保持されている
- MockProviderでAIなしでもデモ可能である
- Gemini APIを使ったAIデモが可能である
- APIキーなしでもアプリ全体が落ちない
- React側にAPIキーやファイルI/O処理がない

### 14.2 発表デモ完了条件
- ゆうこがニュースを持ってくる演出を見せられる
- ニュース要約が見せられる
- 用語解説が見せられる
- 解説結果をゆうこ辞書へ保存できる
- ゆうこ辞書画面で保存した用語を確認できる
- 再起動後も保存した用語を確認できる
- このソフトの将来拡張として、ガチャやカスタマイズ要素を説明できる
- Gemini APIが使えない場合でも、MockProviderで同じ流れを見せられる

> ※ 友情ポイント・ランク進捗・ランクアップ表示・ランクアップ報酬は追加機能。実装済み（PR #52等）だが、MVP必須の完了条件・必須デモ手順には含めない。発表デモで見せる場合も、任意の追加要素として扱う。

- 日次上限は簡易実装で可

- ランクアップ体験を最低1回デモできる（MVP必須ではない）
- ポイントがクリック連打で二重加算されにくい

#### 実装状況

## 16. MVP開発時の注意点

### 16.1 作りすぎない
MVP段階で、ガチャ、デコ、Drive移行、メール連携まで本格実装しない。  
まずはニュース理解補助として成立させる。

### 16.2 ゆうこを置物にしない
ゆうこは単なる画像ではなく、以下の役割を最低限持つこと。

- ニュースを紹介する
- 解説を伝える
- ランクアップを知らせる
- 使いたくなる雰囲気を作る

### 16.3 AI依存しすぎない
AIが使えない状態でも、MockProviderでUIデモができること。  
また、本文抽出やMarkdown整形をAI任せにしない。

### 16.4 軽量性を崩さない
常駐アプリとして、MVP段階から重い構成を避ける。  
派手な演出よりも、軽く自然に動くことを優先する。

### 16.5 React側に責務を寄せすぎない
React側はUI表示と操作受付を担当する。  
ニュース取得、AI呼び出し、保存、ポイント加算、通知回数管理はRust側へ置く。

### 16.6 Tauri commandを増やしすぎない
MVPでは、画面から必要な操作だけをcommand化する。  
汎用的なファイル操作やURL取得commandは作らない。

## 17. まとめ
MVPでは、全機能を完成させるのではなく、以下の核を成立させる。

> ゆうこがニュースを届け、AIが要約し、難しい用語をその場で解説し、少しずつ関係性が育つ。

この体験が成立すれば、発表時点で本プロジェクトの価値は十分に伝わる。

Tauri版MVPでは、React / TypeScriptで画面とゆうこの体験を作り、Rustでニュース取得、AI連携、ローカル保存、辞書、友情ランク、通知状態を支える。  
ガチャ、デコ、Google Drive移行、メール通知補助などは魅力的な要素であるが、MVPでは将来拡張として位置づけ、まずはニュース理解補助とゆうこ体験を優先する。
