# 進捗管理画面 運用手順

## 1. この手順書の目的

- **進捗管理画面を使うメンバー向け**の手順書です。
- まずは **画面操作で迷わないこと** を目的にします。
- 内部実装の詳細ではなく、**利用者が何をすればよいか** を中心に書いています。
- 分からないときは、この手順書を AI に貼って相談してもかまいません（そのため、専門用語は最小限にしています）。

---

## 2. 進捗管理の正本（いちばん大事な前提）

- **進捗の正本（マスター）は Firestore / Firebase です。**
- 進捗管理画面は、**Firestore の内容を表示・更新する**画面です。画面で操作すると Firestore が更新されます。
- **Markdown ファイル**（`docs/00_project/developタスクチェックリスト.md` など）は、
  - AI にタスクを読ませるための材料
  - バックアップ
  - Git 上のスナップショット
  として使います。
- **Markdown への反映は即時ではありません。** 自動同期（GitHub Actions）のタイミングで反映され、遅延したり実行されないこともあります。
- したがって、**Markdown が古く見えても、進捗管理画面 / Firestore の状態を正**とします。
  「画面と Markdown が食い違う」ときは、**画面（Firestore）を信じてください。**

> 以前は Markdown 中心でしたが、リアルタイムに近い共有がしづらいため、現在は Firebase / Firestore 管理へ移行しています。

---

## 3. 画面でできること（ざっくり）

進捗管理画面（Firestore 表示）では、主に次のことができます。

- **タスク一覧を見る**（カテゴリ・状態ごとに並びます）
- **タスクの状態（ステータス）を確認する**
- **作業を開始する**（担当ブランチ名を登録して Doing にする）
- **ステータスを変更する**（差し戻し・調整など）
- **Review にする**（レビュー待ちにする）
- **Review 完了で Done にする**（人が確認してから完了にする）
- **owner（担当）/ notes（共有メモ）を編集する**
- **Done になったタスクは、基本的に編集しません**（完了記録として扱います）

---

## 4. ステータスの意味

| ステータス | 意味（利用者向け） |
|---|---|
| **Todo** | これからやる。まだ着手していない。 |
| **Next** | 次にやる予定。Todo より優先度・着手が近い。 |
| **Doing** | 作業中。担当ブランチで実装している。 |
| **Review** | レビュー待ち。人の確認が必要な状態。 |
| **Blocked** | 何かの理由で止まっている（依存待ち・要相談など）。 |
| **Done** | 完了。基本的にこれ以上編集しない。 |

---

## 5. 基本操作

> 画面を見ながら操作できるように、手順形式でまとめています。
> 各操作の後、**Firestore のタスクが更新**されます。**Done にする操作のときは、Markdown 同期要求（後述）も同時に作られます。**

#### 作業を開始する（＋作業ブランチ名を登録する）

目的:
- これから着手するタスクを **Doing** にし、**担当ブランチ名**を登録する。

手順:
1. 対象タスクのカードにある **「作業開始」** ボタンを押す。
2. 担当（owner）が未設定なら、確認メッセージが出る。設定してから始めるか、そのまま進めるかを選ぶ。
3. ブランチ名の入力欄（初期値が入っている場合はそのまま使える）で、**作業ブランチ名を確認・編集**して OK。
   - キャンセルすると、作業開始は中止されます（Firestore は更新されません）。

押した後に起きること:
- Firestore のタスクが **Doing** になり、**branchName** が保存される。

注意:
- ブランチ名が空だと開始できません。
- ここで登録した branchName は、後の「PR とタスクの紐づけ」に使われます。**実際に作るブランチ名と一致**させてください。

#### ステータスを変更する（差し戻し・調整）

目的:
- タスクを別のステータスへ変更する（例: Doing → Todo に戻す、Todo → Next にする など）。

手順:
1. 対象タスクの **「Status変更」** の中から、変更先のステータスボタンを押す。

押した後に起きること:
- Firestore のタスクの status が更新される。
- （Done を選んだ場合のみ）完了扱い（completed = true）になり、**Markdown 同期要求も作られる**。

注意:
- **作業中（Doing）のタスクでは、Status変更に「Review」「Done」は出ません**（誤操作防止のため）。
- **Review のタスクでは、Status変更ボタン自体が出ません**。Done にするときは下記「Review 完了で Done にする」を使ってください。

#### Review にする

目的:
- 人の確認が必要なタスクを **Review**（レビュー待ち）にする。

手順:
1. Todo / Next / Blocked のタスクなら、**「Status変更」→「Review」** を押す。

押した後に起きること:
- Firestore のタスクが **Review** になる。

注意:
- **作業中（Doing）のタスクは、PR をマージすると自動判定で Review や Done へ動くことがあります**（マージ後の自動処理）。手動で Review にしたい場合のみ、上記の Status変更を使ってください。

#### Review 完了で Done にする

目的:
- レビューが終わったタスクを、人が確認したうえで **Done** にする。

手順:
1. Review のタスクにある **「レビュー完了（Doneにする）」** ボタンを押す。
2. 確認ダイアログ（「このタスクをDoneにしますか？」）で **OK** を押す。

押した後に起きること:
- Firestore のタスクが **Done**（completed = true・完了時刻を記録）になる。
- **Markdown 同期要求も同時に作られる**（次回の同期で Markdown に反映される）。

注意:
- archived（アーカイブ済み）や、すでに完了しているタスクは Done にできません（安全のため弾かれます）。

#### Todo / Next / Blocked などから Done にする

目的:
- レビュー不要の軽微なタスクを、直接 **Done** にする。

手順:
1. Todo / Next / Blocked のタスクで、**「Status変更」→「Done」** を押す。

押した後に起きること:
- Firestore のタスクが **Done**（completed = true）になる。
- **Markdown 同期要求も同時に作られる**。

注意:
- Doing のタスクにはこの導線はありません（Status変更に Done が出ません）。いったん適切なステータスに戻すか、PR マージ後の自動処理・Review 完了を使ってください。

#### owner（担当）/ notes（共有メモ）を編集する

目的:
- タスクの担当者や、共有メモを更新する。

手順:
1. 対象タスクの **担当 / メモの編集** ボタンを押す（カードが編集モードになる）。
2. owner はドロップダウンから選ぶ（既存の候補外の名前が入っていても消えません）。
3. notes を編集して保存する。

押した後に起きること:
- Firestore のタスクの owner / notes（と更新時刻）が更新される。

注意:
- **Done のタスクは owner / notes を編集できません**（完了記録の保護）。

## 6. PRマージ後の自動Done化について

PR（プルリクエスト）を develop にマージしたとき、条件を満たすと、**紐づく Firestore タスクが自動で Done になる**ことがあります。これを決めるのが、**PR本文の「Done許可チェック」** です。

- PR本文にある次のチェックが **`[x]`（チェック済み）のときだけ**、マージ後の **自動Done化の対象** になります。
- **未チェック（`[ ]`）なら、PRをマージしても自動Done化しません**（タスクはそのままの状態で残ります）。
- このチェックは、**「このPRのマージで、紐づくタスクを Done にしてよいか」を、あなた（PR作成者）が明示するためのもの** です。

チェックボックスの文言（PR本文テンプレートに入っています）:

```md
- [ ] このPRのマージ後、紐づくFirestoreタスクをDoneにしてよい
```

チェックを付けるときの注意:

- **自信がない場合は、未チェックのままにしてください**（未チェックのほうが安全側です。あとから人手で Done にできます）。
- **誤ってチェックしないよう注意してください**。チェックしたままマージすると、対象タスクが Done になります。
- 大きなタスクの途中のPRや、複数タスクにまたがるPRでは、**チェックしない**のが基本です。
- 迷ったら、マージ前に担当者・管理者に確認してください。

## 7. Markdown への反映について

- 画面で操作すると **Firestore はすぐ更新**されますが、**Markdown への反映は自動同期のタイミング**になります。
- 自動同期（GitHub Actions の定期実行）は、**即時性を保証しません**。混雑などで**遅延・実行されない**ことがあります。
- **急いで Markdown に反映したいとき**は、管理者または担当者が GitHub Actions の
  **`Sync Firestore to Markdown`** を **手動実行**します（Actions 画面の「Run workflow」）。
- Done 操作をしたタスクは、**Markdown 同期要求**が作られるため、次の自動同期または手動実行で Markdown に反映されます。

> くり返しになりますが、**Markdown が古く見えても、画面（Firestore）の状態が正**です。

---

## 8. やってはいけないこと

- **Firestore Console で直接値を書き換えない。** 進捗の更新は、必ず進捗管理画面から行ってください（直接編集は状態の整合が崩れる原因になります）。
- **Done 済みのタスクを勝手に元に戻さない。** Done は完了記録です。戻す必要があるときは、担当者・管理者に相談してください。
- **PR本文の「Done許可チェック」を、意味が分からないままチェック済みにしない。**（→「6. PRマージ後の自動Done化について」を参照。自信がなければ未チェックのまま）
- **Markdown だけを見て「最新状態」だと判断しない。** 正本は Firestore / 進捗管理画面です。Markdown は反映が遅れることがあります。
- **自動同期PR（`Sync Firestore to Markdown` が作るPR）の差分を確認せずにマージしない。** 中身を見てからマージしてください。
- **Firebase の APIキー・認証情報・秘密情報を AI に貼らない。**（→「10. AIに相談するときに渡す情報」も参照）

## 9. 困ったとき

#### 画面の表示が古いように見える

- ブラウザを更新（再読み込み）する。
- **`?source=firestore` を付けて開いているか**確認する（この表示のときだけ、Firestore の内容が表示され、操作もできます）。

#### Done にしたのに Markdown が変わらない

- **Markdown は即時反映ではありません。** これは正常です。
- 自動同期（GitHub Actions の schedule）を待つと反映されます。
- **急ぐ場合は、管理者または担当者に「手動同期（`Sync Firestore to Markdown`）」を依頼**してください。

#### PR をマージしたのにタスクが Done にならない

- **PR本文の「Done許可チェック」がチェック済み（`[x]`）だったか**確認する（未チェックだと自動Done化しません）。
- **タスクと PR が紐づいているか**確認する（taskCode / branchName が一致しているか）。
- 自信がない場合は、担当者に確認してください。

#### 何を押せばよいか分からない

- 対象タスクの **status（今の状態）と、やりたいこと（目的）** を確認する。
- それでも分からなければ、**チャットで確認**してください（→「10. AIに相談するときに渡す情報」）。

#### ボタンを押してもエラーになる

- 別の人が先に状態を変えた等で、弾かれることがあります（安全のための動作です）。
- 画面を再読み込みして、最新状態で操作し直してください。

> くり返しになりますが、**画面（Firestore）が正**です。Markdown が古く見えても、画面の状態を優先してください。

## 10. AIに相談するときに渡す情報

チャットで相談・質問するときは、次の情報を貼ると、状況が伝わりやすくなります。

- どの画面で困っているか
- 対象タスクの **title / taskCode**
- 現在の **status**
- 押そうとしている **ボタン**
- 期待している状態（どうなってほしいか）
- 実際に起きたこと
- **エラーメッセージがあれば、その全文**

**AI に貼らないでください（重要）:**

- Firebase の APIキー
- 認証情報（トークン・サービスアカウント等）
- 秘密情報
- 個人情報
- 不要なスクリーンショット（必要な範囲だけにする）
