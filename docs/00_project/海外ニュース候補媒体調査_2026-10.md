# 海外ニュース候補媒体調査（英語の技術・国際ニュース）2026-10

作成日: 2026-10-27 ／ 判断台帳: D163（海外ニュース機能の事前調査）、D164（企業の技術ブログ4媒体の追加調査）／ 関連: [リリース前調査_2026-10](リリース前調査_2026-10.md)
観点の基準: [媒体ToS・AI要約運用方針](../01_setup/媒体ToS・AI要約運用方針.md) §4 チェックリスト（「可否不明が1つでも残る媒体は許可リストへ入れない」）

> この文書は公開ページから読み取れた**事実の整理**で、法的助言ではない。最終判断はオーナー（藤井）が行う。公開や社外への提示の前には法務・専門家の確認が要る。
> 規約の引用は短い語句にとどめ、出典URLを付けた。確認日はいずれも **2026-10-27**。規約は改定されるため、判断の直前に原文を再確認すること。
> 確認できなかったことは「未確認」と書いた。推測では埋めていない。

> **調査の制約**
> - 一部の公式ページ（Condé Nast・Vox Media・Reuters・AP・BBC・The Guardian・DW・NHK World・OpenAI の規約ページなど）は、本調査の環境から本文を取得できなかった（取得ツール側で拒否・403・タイムアウト）。該当項目は「未確認」とした。
> - robots.txt と RSS は全媒体で直接取得できた（§4 のコマンド）。RSS の抜粋の長さは、この日に取得したフィードの実測値。

## 0. 判断が必要な点（藤井さん向け）

1. **海外媒体でも「本文ページの取得＋AI要約」はほぼ全滅に近い**
   - 国際ニュースの大手（Reuters・BBC・Al Jazeera・The Guardian）は、robots.txt のコメントや規約で、自動収集・AI 利用・要約を**明文で禁止**している。Reuters は robots.txt でサイト全体を拒否している。
   - 技術ニュースも、ほとんどが「個人・非営利の利用に限る」「スクレイピング禁止」「改変・翻訳・二次的著作物の禁止」を規約に書いている。
   - 選択肢:
     - (a) 試作は**RSS に入っている要旨だけ**を使い、記事ページは取得しない（本調査の提案。§2）。
     - (b) 試作も見送り、許諾を取る媒体を先に決める。
     - (c) 論文・公式ブログなど、ニュース媒体以外を主にする。
       - D164 で、企業の技術ブログ4つ（GitHub・AWS・Hugging Face・Cloudflare）を追加で調べた（§1.2「企業の技術ブログ」）。
2. **試作（20記事程度）をどこまでで閉じるか**
   - 多くの規約は「個人・非営利」を前提にしている。チーム内の実験がこれに当たるかは、規約上はっきりしない。
   - 試作は「チーム内だけ・保存は検証後に消す・画面キャプチャを外に出さない」で閉じることを提案する。
3. **社内発表（デモ）で海外記事を画面に出すか**
   - デモで出すなら、§2 の試作用媒体のうち、規約上の制約が最も少ないもの（arXiv・公式ブログ）に絞るのが安全。
   - 国際ニュースをデモで出すなら、NPR・DW は「個人・非営利」の条件があるため、事前に法務確認か、媒体への問い合わせが要る。
4. **翻訳を伴う要約の扱い**
   - 英語記事を日本語で要約することは、一般的な著作権の考え方では「翻訳」「翻案」に当たる場合がある（§1.5）。規約でも TechCrunch・MIT Technology Review などは翻訳・二次的著作物の作成を禁止している。
   - 公開を視野に入れるなら、この点は法務確認が必須。

## 1. 媒体ごとの規約調査

### 1.1 アプリの使い方（照合の前提）

- 既存の国内媒体と同じ流れを想定する（[リリース前調査 §1.1](リリース前調査_2026-10.md)）。
  - RSS で一覧を取る → 記事ページの HTML から抜粋（上限あり）を取る → 同梱ローカルLLM で日本語の要約・解説・要点を作る。全文は表示しない。
- 海外媒体では、英語から日本語への**翻訳を伴う要約**になる。全文翻訳は載せない前提。
- 現在の User-Agent は `yuuko-news-biyori/0.1`。robots.txt と Crawl-delay は参照していない。

### 1.2 場面ごとの判定（要約）

凡例:

- 場面: **実験**＝開発中にチーム内で試す／**デモ**＝社内発表で画面に出す／**公開**＝不特定に配布する（D151 により当面予定なし）。
- 判定: **使える**／**条件付き**（条件を括弧内に書く）／**使えない**／**未確認**（規約本文を確認できず判断できない）。
- 「RSSのみ」＝RSS に入っている見出し・要旨だけを使い、記事ページは取得しない。
- 判定は**規約上の記述**と robots.txt に基づく。著作権法上の評価は §1.5 に分けた。

### 1.4 媒体別の詳細

#### arXiv（技術・論文）

確認したページ:

- API 利用規約 https://info.arxiv.org/help/api/tou.html
- 再利用の案内 https://info.arxiv.org/help/license/reuse.html
- robots.txt https://arxiv.org/robots.txt 、https://export.arxiv.org/robots.txt

項目別:

- **メタデータ**: 記述的メタデータは CC0 1.0 で利用できる（API 利用規約）。
  - アブストラクトがこの「記述的メタデータ」に含まれるかは、今回読んだページからは**未確認**。
- **論文本文**: arXiv は著作権者ではない。再配布には著作権者の許可が要る。個人利用・研究目的での取得と利用は可。
  - 論文ごとのライセンスは RSS の `dc:rights` に入っている（CC BY なら条件付きで再利用可）。
- **取得間隔**: 旧来の API・RSS・OAI-PMH は「3秒に1回まで」「同時接続1本」。
  - robots.txt: arxiv.org は `Crawl-delay: 15`。export.arxiv.org は全拒否。rss.arxiv.org に robots.txt はない（404）。
- **ブランド**: arXiv が支持・後援しているかのような表示は不可。
- **所見**: 規約上の制約が最も少なく、RSS の要旨も長い。ただし「ニュース」ではなく論文の新着。

#### Microsoft 公式ブログ（blogs.microsoft.com）

確認したページ:

- 利用規約 https://www.microsoft.com/en-us/legal/terms-of-use （最終更新 2022-02-07）
- robots.txt https://blogs.microsoft.com/robots.txt

項目別:

- **利用範囲**: 特記がない限り「個人・非営利の利用」に限る。文書は改変しないこと。
- **改変・複製**: サービス上の情報の改変・複製・配布・表示を禁止。
- **自動取得**: サイト全般については記載なし（AI サービスについてのみスクレイピング禁止の記載がある）。
- **robots.txt**: `crawl-delay: 10`。記事は拒否していない。
- **RSS**: 記載なし。フィードには全文が入っている。

#### Google 公式ブログ（blog.google）

確認したページ:

- Google 利用規約 https://policies.google.com/terms?hl=en （2026-07-30 発効）
- robots.txt https://blog.google/robots.txt

項目別:

- **自動取得**: robots.txt などの指示に反する自動取得を禁止している。blog.google の robots.txt は検索ページ以外を拒否していない。
- **他者のコンテンツ**: 他者のコンテンツは、その権利者の許可なしに使えない、とある（ブログ記事の権利者は Google）。
- **ブログ固有の規約**: 未確認（blog.google がこの規約の対象かは、ページ上では確認していない）。

- robots.txt https://openai.com/robots.txt は1パス以外を許可。RSS は要旨が短い（約150字）。

#### TechCrunch（TechCrunch Media, LLC）

確認したページ:

- 利用規約 https://techcrunch.com/terms-of-service/ （発効 2025-05-01）
- RSS 利用規約 https://techcrunch.com/rss-terms-of-use/ （日付の記載なし）
- robots.txt https://techcrunch.com/robots.txt

項目別:

- **RSS**: 条件付き。
  - ニュースリーダーなどのアプリで、**フィードに含まれる内容だけ**を表示できる。
  - TechCrunch の帰属表示と、全文記事へのリンクが必須。
  - 帰属・リンクの削除や「フィード内容の改変」は不可。広告の組み込みも不可。
- **サイト規約**:
  - 「個人・非営利の利用」に限る。
  - robot・spider・scraper などでのデータ抽出を禁止。
  - 許可なしの**翻訳・二次的著作物の作成**を禁止。
- **robots.txt**: 記事は拒否していない。主要な AI クローラーは全拒否。
- **所見**: RSS の見出し＋要旨をそのまま出してリンクする使い方は RSS 規約に沿う。日本語要約は「改変」「翻訳」に当たる可能性がある。

#### MIT Technology Review

確認したページ:

- 利用規約 https://www.technologyreview.com/terms-of-service/ （最終更新 2023-09-06）
- robots.txt https://www.technologyreview.com/robots.txt

項目別:

- **利用範囲**: 「個人利用のみ」。商用利用は不可。
- **自動取得**: robot・spider・scraper などでのデータ抽出を禁止（検索エンジンの索引作成は例外）。
- **AI**: 書面の同意なしに、AI・機械学習の作成・学習・改良に使うことを禁止。
- **複製・改変**: 書面の事前許可なしの複製・改変・再掲載を禁止。許可は個別判断。
- **RSS**: サービスの一部として扱われ、RSS 固有の条件はない。
- **robots.txt**: 記事は拒否していない。主要な AI クローラーは全拒否。

#### The Register（Situation Publishing）

確認したページ:

- 利用規約 https://www.theregister.com/profile/terms_and_conditions_of_use （日付の記載なし）
- robots.txt https://www.theregister.com/robots.txt （コメント上の最終更新 2026-06-18）

項目別:

### 1.5 一般的な著作権の考え方（一般論・要法務確認）

規約とは別に、日本で利用する場合の一般的な考え方を整理する。個別の当てはめは法務確認が要る。

- **外国の記事も保護される**: ベルヌ条約により、英語の記事も日本の著作権法で保護されるのが一般的な理解。
- **事実そのもの**: 事実や、事実を伝えるだけの短い報道（著作権法 10条2項）は著作物に当たらないとされる。ただし通常の記事は表現に創作性があり、保護される前提で扱う。
- **翻訳・要約**: 翻訳や要約は、翻訳権・翻案権（27条）にかかわる場合がある。英語記事を日本語で要約するのは、両方の要素を含みうる。
- **30条（私的使用）**: 個人・家庭内などの限られた範囲が対象。チーム内の業務利用は含まれない可能性が高い。
- **30条の4（享受を目的としない利用）**: 情報解析などは、著作権者の利益を不当に害しない範囲で認められる。ただし要約を画面に出して人が読むことは、「享受」に当たり、この条文の範囲外となる可能性がある。
- **32条（引用）**: 公正な慣行に合い、正当な範囲内であることが要件。一般に、主従関係・明瞭な区別・出所の明示（48条）が求められる。AI の要約が主になる表示は、引用の要件を満たしにくい。
- **47条の5（軽微利用）**: 所在検索などのサービスに付随する軽微な利用を認める規定。見出し＋短い要旨＋リンクの表示が当てはまるかは、要件の確認が要る。
- **規約は契約**: 規約は著作権法とは別の契約上の約束で、準拠法は多くが外国法（例: TechCrunch はニューヨーク州法）。著作権法上許される利用でも、規約違反の問題は別に残りうる。

## 2. 試作で使う媒体の提案

試作の目的は「20記事ほどで日本語要約の質と時間を測る」こと。規約上のリスクを下げるため、次の条件で行うことを提案する。

- **RSS のみ**を使う。記事ページは取得しない。
- 取得は手動か、媒体の指定より長い間隔で行う。
- チーム内だけで試す。保存したデータは検証後に消す。画面キャプチャは外に出さない。

| 区分 | 媒体（フィード） | 理由 | 注意 |
|---|---|---|---|
| 技術 | arXiv（cs.AI・cs.CL の新着RSS） | 規約上の制約が最も少ない（メタデータは CC0、論文ごとのライセンスが RSS に入っている）。要旨が約1,500字あり、要約の質を測りやすい | 3秒に1回まで。論文で、ニュースとは文体が違う。アブストラクトが CC0 の範囲かは未確認 |
| 技術 | Microsoft 公式ブログ | 要旨が約470字ある。自社の発表で、報道記事より権利上の摩擦が小さいと見込める | 規約は個人・非営利、改変不可。`crawl-delay: 10` |
| 技術（補欠） | Google 公式ブログ | robots.txt が記事を拒否しておらず、Google 規約も robots.txt の範囲内の自動取得を禁止していない | 要旨が約130字と短い |
| 国際 | NPR（World） | 国際媒体で唯一、RSS の利用条件（個人・非営利・帰属表示）が公式に書かれている | 要旨が約170字と短い。「個人・非営利」に限る |
| 国際（補欠） | DW（英語・全記事） | 要旨が約200字。robots.txt で記事を拒否していない | robots.txt のコメントで個人・非営利に限定、自動スクレイピングは要許可。規約本文は未確認 |

使わない媒体と理由:

- **The Guardian**: 要旨は長い（約600字）が、AI 関連の利用を明示的に断っている。
- **TechCrunch**: RSS 規約が「改変不可」。要約の試作には向かない（見出し＋要旨＋リンクの表示なら可）。
- **MIT Technology Review**: 全文入りの RSS だが、規約が個人利用のみ・改変不可。
- **Reuters・AP・BBC・Al Jazeera・The Register**: robots.txt や規約で自動取得・AI 利用・要約を禁止。

追加候補（D164 の企業の技術ブログ。試作に使えるか）:

- **Cloudflare Blog**: 使える。AI への入力を robots.txt で明示的に許可しており、技術ブログの中で最も根拠がはっきりしている。要旨は約200字。
- **AWS What's New**: 使える（チーム内・RSSのみ）。要旨が約1,350字と長く、要約の質を測りやすい。ただし規約が個人利用のみ・派生的な利用を禁止しているため、デモに出すかは要確認。
- **GitHub Blog**: 使える（RSSのみ）。禁止条項は少ないが許諾もない。要旨は約260字。補欠向き。
- **Hugging Face Blog**: 向かない。RSS に要旨がなく、RSS だけでは要約できない。見出し＋リンクの一覧としてなら使える。

国際ニュースの要旨は短い（100〜200字）。試作では「短い要旨から、どこまで役に立つ日本語要約を作れるか」もあわせて測る。足りない場合に記事ページを取得するかは、許諾の取り方とあわせて別途判断する。

## 3. アプリ側で必要になりそうな配慮

- **出典の明示**: 媒体名を常に表示する（NPR・TechCrunch などは帰属表示が条件）。
- **元記事へのリンク**: 全文記事へのリンクを必ず付ける。ユーザー操作で開く（既存方針と同じ）。
- **英語記事の表示**: 「英語の記事」「日本語の要約は AI が作成」と分かる表示を付ける。誤訳の可能性も一言添える。
- **原題の表示**: 英語の原題をそのまま出す。日本語の見出しは「AI による訳」と区別する。
- **要約の長さの上限**: 要約は短くする（例: 数文、目安 200〜300字）。原文の量を超えない、全文翻訳に見えない長さにする。
- **全文翻訳をしない**: 段落ごとの対訳や、全文の翻訳ボタンは作らない。
- **RSS のみモード**: 媒体ごとに「記事ページを取得しない（RSS の要旨だけ使う）」を設定できるようにする。
- **AI 要約の可否フラグ**: 媒体ごとに「AI 要約しない（見出し＋要旨＋リンクだけ）」を設定できるようにする。
- **取得間隔**: 媒体ごとの最小間隔を持つ。例: arXiv は3秒に1回以上空ける、Microsoft は10秒、Hacker News は30秒（いずれも robots.txt や API 規約の値）。
- **robots.txt の扱い**: 取得前に robots.txt を確認する仕組みを検討する（[リリース前調査 §0-6](リリース前調査_2026-10.md) と同じ論点）。The Register のように既定で全拒否のサイトもある。
- **User-Agent**: アプリ名と連絡先が分かる User-Agent にする。ブラウザに偽装しない。
- **保存の範囲**: 抜粋の保存長を媒体ごとに決める。RSS に全文が入っていても、上限を超えて保存しない。
- **Gemini（任意）への送信**: 海外媒体の抜粋は、外部 AI に送らない設定を既定にすることを検討する（規約で AI 利用を断る媒体が多いため）。
- **許可リスト**: 追加する場合は、フィードと記事の両ドメインを `network_allowlist.json` に追加する必要がある（本調査では触れていない）。

## 4. 調査で使ったコマンド（再現用）

robots.txt の取得（媒体ごとに実行）:

```sh
curl -s -m 20 -A "Mozilla/5.0" -o "<domain>.txt" "https://<domain>/robots.txt"
```

D164 の追加調査（GitHub・AWS・Hugging Face・Cloudflare）では、robots.txt も curl の既定の User-Agent で取得した（ブラウザに偽装しない）:

```sh
curl -s -m 20 -o "<domain>.txt" "https://<domain>/robots.txt"
```

RSS の取得（curl の既定の User-Agent）:

```sh
curl -sL -m 30 -o "<name>.xml" "<フィードURL>"
```

要旨の長さは、各 `item`／`entry` の `description`／`summary` と `content:encoded`／`content` から HTML タグを除き、文字数の中央値と最大値を数えた（Python 標準ライブラリの `xml.etree.ElementTree`）。
