# ai-context（AI作業コンテキスト導線）

## 目的

AI（Claude Code / Codex）が開発タスクを始めるとき、**リポジトリ全体を事前走査せずに**、そのタスクに必要な資料・ソース・対象外領域を最初に判断できるようにするための入口集である。

初期探索での利用枠（トークン）消費を減らすことが狙い。**具体的なトークン削減率は断定しない**（環境・タスクにより変動する）。「不要な初期探索を減らすための仕組み」として扱う。

## Claude Code / Codex の両方で使う

- 共通の作業開始ルールは、リポジトリルートの `AGENTS.md`（§0「作業開始ルール」）を基準とする。
- Claude Code は `CLAUDE.md` から同じ導線を参照する（`CLAUDE.md` は `@AGENTS.md` で共通ルールを読み込む）。Codex は `AGENTS.md` を参照する。
- 本 `ai-context` は、そのルールが参照する「領域別の入口」を置く場所である。
- 領域別の詳細ルール `.claude/rules/*.md` は、Claude Code が各ルールの `paths` に一致するファイルを扱ったときに読み込む（`ai-context` とは別系統。Codex は `.claude/rules/` を自動では読まないため、必須ルールは `AGENTS.md` にある）。

## 作業開始時の読み方

1. タスクで指定された `docs/00_project/ai-context/<領域>.md` を最初に読む。
2. 指定がなければ、この README で対象領域を選び、その `<領域>.md` を読む。
3. `<領域>.md` の「最初に読むファイル」に挙がったファイルから調査を始める。
4. 「関連設計書」は、必要な章だけを優先して読む（設計書全体を頭から読まない）。
5. 「対象外」に挙がった領域には、明確な必要性がない限り触れない。

## タスクプロンプトからの指定方法

タスク開始プロンプトに、最初に読む入口を明示する。例:

```text
AGENTS.md と
docs/00_project/ai-context/settings.md
を最初に確認してください。

記載された対象ファイルから調査を開始し、
最初からリポジトリ全体を探索しないでください。
```

Codex でも同じプロンプトをそのまま使える（共通ルールは `AGENTS.md` を基準とするため）。

## 各コンテキストファイルに書く項目

領域別ファイル（例: `settings.md`）には、少なくとも次を書く。

- **対象領域**: この入口が扱う機能範囲。
- **最初に読むファイル**: 実在するソースの相対パス（存在しないパスは載せない）。
- **関連設計書**: 実在する設計書のパスと、優先して読む章。
- **重点確認項目**: 変更時に特に確認する関数名・フィールド名・制約。
- **対象外**: このタスクで触れない領域（git 外設定・別機能など）。
- **推奨確認コマンド**: その領域の変更で走らせる最小限のコマンド。

**書かないこと**: 設計書本文やソース全文のコピー。参照先（パスと章）を示すにとどめる。同じ内容を複数ファイルへ重複記載しない。

## コンテキストファイルを増やす判断基準

- 「同じ領域のタスクを、また全体探索から始めそう」なときに、その領域用の `<領域>.md` を追加する。
- 1タスク限りの一時メモは追加しない。
- 既存ファイルへ追記で足りる場合は新規作成しない。
- 画面単位ではなく、複数タスクで共有できる機能単位で分ける（通知とホーム画面のように状態・遷移を共有する範囲は分割しない）。
- news-pipeline / archive 等は後続で必要になったとき追加する。

## 内容が古くなった場合の更新方針

- パス・関数名・章番号が実装とずれたら、**実装（正）に合わせて入口ファイルを更新**する。
- 入口ファイルは「参照先の地図」であり、実装の詳細を写す場所ではない。ずれやすい本文コピーは持たない。
- 大きな構成変更（ディレクトリ移動・機能統廃合）があった領域は、その入口ファイルの見直しをタスクに含める。

## 全体探索が必要になったときの扱い

- 入口だけで判断できない場合に限り、追加探索を行う。
- そのときは「何を確認するために、どこを読むか」を短く説明してから読む（無言の全体走査はしない）。
- 探索で分かった恒久的に有用な入口情報は、該当 `<領域>.md` へ最小限で反映する。

## 現在ある入口

- [`yuuko-home.md`](./yuuko-home.md) — ゆうこ通知・吹き出し・軽量プレビュー・SCR-001 メイン画面（おすすめ記事表示・ゆうこ本体レイアウト）と通知操作のRust側接続。
- [`term-dictionary.md`](./term-dictionary.md) — SCR-002 ニュース閲覧画面の文字列選択・用語解説ポップアップ・辞書保存とSCR-004 ゆうこ辞書画面での再利用。
- [`settings.md`](./settings.md) — 設定画面・設定DTO・保存/読み込み（domain / service / repository）と設定テスト。
- [`mvp-demo.md`](./mvp-demo.md) — MVP必須シナリオの通し確認・Windows実機確認・複数機能をまたぐ問題の切り分けと、個別ai-contextへの振り分けハブ。

## タスク内容から入口を選ぶ

| タスクに出てくる語 | 入口 |
|---|---|
| 通知、ゆうこ、吹き出し、軽量プレビュー、ホーム画面、おすすめ記事 | `yuuko-home.md` |
| 文字列選択、用語解説、辞書、ゆうこ辞書画面 | `term-dictionary.md` |
| 設定保存、通知設定（ON/OFF・時間帯・上限）、解説レベル、AI Provider選択 | `settings.md` |
| MVP通しデモ、実機確認、複数機能をまたぐ問題 | `mvp-demo.md` |

- 通知の**設定値の保存**は `settings.md`、通知の**表示・操作**は `yuuko-home.md`。
- 記事の**一覧表示**は `yuuko-home.md`、記事詳細での**用語解説**は `term-dictionary.md`。
- 単一機能の修正は個別ai-contextを直接使う。`mvp-demo.md` は**複数機能をまたぐ横断確認のときだけ**使う。
- 該当する入口がない領域（ニュース取得パイプライン・アーカイブ・ガチャ等）は、上記の追加判断基準に従う。
