## 0. 判断が必要な点（藤井さん向け）

1. **既定の取得元11媒体の扱い**（§1）
   - 規約や robots.txt で、自動取得・蓄積・AI要約を**明文で禁止**している媒体がある：**BBC**、**東洋経済オンライン**。sorae は「要約にも許諾が要る」と明記している。
   - このほか多くの媒体が「私的使用の範囲を超える複製」「営利目的の利用」を禁止している（ハフポスト、Business Insider Japan、ライフハッカー、ITmedia など）。社内配布や公開は「私的使用」に当たらない可能性が高い。
   - 既存の運用方針 §4 に照らすと、**11媒体とも「可否不明」か「禁止」の項目が残る**。方針どおりに運用すると、どの媒体も同梱の既定値として残せない。
   - 選択肢:
     - (a) 高リスクの媒体を既定値から外す。
     - (b) 全媒体を「見出し＋RSSの要旨＋リンク」だけの表示にする。本文の取得・保存・AI要約はしない。
     - (c) 媒体ごとに問い合わせ、許諾が得られた媒体だけ本文を使う。
     - (d) 既定値を空に戻す（D138 の見直し）。
2. **社内配布と公開の線引き**
   - 配布範囲（社内だけか、一般公開か）で、規約の「私的使用」「営利目的」への当てはまり方が変わる。どこまで配るかを先に決めたい。
3. **Gemini（任意）への本文抜粋の送信**
   - 本文抜粋を第三者の AI に送ることを明示的に許可している媒体はない。東洋経済と BBC は、AI による要約や RAG への投入を明文で禁止している。
   - 選択肢: 媒体ごとに送信を止める／Gemini 経路では見出しと RSS の要旨だけを送る。
4. **VC++ ランタイムの配り方**（§3）
   - 現在は、Build Tools の Redist フォルダから DLL をコピーして llama-server の隣に置いている（app-local 方式）。
   - この方式は Microsoft の再頒布リストの対象内だが、**有効な Visual Studio ライセンスを持っていることが前提**になる。
   - 決めること:
     - チームが有効な VS ライセンスを持っているか（Community の利用条件を満たすか）の確認。
     - 方式の選択: 現状維持／vc_redist.x64.exe をインストール時に実行する／llama.cpp を自前で静的リンクビルドする。
5. **THIRD_PARTY_NOTICES の同梱**（§2.5）
   - 現在は、ローカルLLMの部品のライセンス本文（`local_llm/LICENSES/`）だけを同梱している。npm・Rust crate・フォントの表記は入っていない。
   - 生成方法と、どの画面から見せるか（設定画面に「ライセンス」を設けるか、ファイル同梱だけにするか）を決めたい。
6. **robots.txt と Crawl-delay**
   - アプリは robots.txt を読んでいない。
   - GIGAZINE は `Crawl-delay: 100`、サッカーキングは `Crawl-delay: 10` を指定している。BBC は robots.txt のコメントでスクレイピングを禁止している。
   - 取得間隔や robots.txt への対応を実装するかを決めたい。

## 1. 媒体ごとの規約調査

### 1.1 アプリの使い方（照合の前提）

アプリの使い方（確認したコード: `src-tauri/src/services/default_news_sources.rs`、`src-tauri/src/infra/html_fetcher.rs`、`rss_client.rs`）:

- **RSS の取得**: 11媒体分を同梱している。
- **記事ページの取得**: HTML を取得して本文を抽出し、**最大2,000文字の抜粋**を Markdown としてローカルに保存する。
- **AI 処理**:
  - 同梱のローカルLLMで要約・再説明を作る。
  - Gemini キーが設定されている場合は、抜粋を Gemini にも送る（最大1,500文字の抜粋を使う箇所がある）。
- **表示**: 再説明・要点・短い抜粋と、元記事へのリンクを表示する。
- **取得の振る舞い**:
  - User-Agent は `yuuko-news-biyori/0.1`。
  - robots.txt や Crawl-delay は参照していない。

### 1.4 全体所見

1. **RSS と AI について明文がある媒体は少ない。** RSS の利用（ITmedia・BBC）や AI・要約（東洋経済・BBC・sorae）を規定している媒体はあるが、大半は「記載なし」だった。ただし「記載なし」を許可と読むことはできない。11媒体中10媒体が、無断の複製・転載や、私的使用を超える利用を禁止している。
2. **最大の論点は保存と要約。** 本文抜粋（最大2,000文字）のローカル保存と AI 要約は、「複製」「翻案（改変利用）」「蓄積」の規定に触れやすい。見出し、RSS の要旨、リンクだけの表示なら、リスクは大きく下がる。
3. **Gemini 経路は追加のリスクがある。** 第三者のサーバーへ本文抜粋を送ることになる。東洋経済と BBC は明文で禁止している。
4. **robots.txt に対応していない。** GIGAZINE（100秒）とサッカーキング（10秒）の Crawl-delay を守る仕組みがない。
5. **既存の運用方針との関係。** 方針 §4 は「可否不明が1つでも残る媒体は許可リストへ入れない」としている。D138 で同梱した既定値11件は、この基準を満たしていない。

4. ローカルLLM

   - 「(c) Microsoft Corporation」と、再頒布可能コードとして配っている旨（§3）。
6. WebView2
   - 同梱はしていないので、表記の義務はない。必要なら一言触れる。

**新しい依存を入れずに作る方法**

- npm:
  - `pnpm licenses list --prod --json` の `paths` に各パッケージの場所が入っている。
  - その場所の `LICENSE*` を Node の標準機能（`fs`）で読んで連結する。

- CI で差分を検出すれば、依存の更新に追従できる。
- cargo-about や license-checker などの外部ツールは使わずに済む。
- 未決事項: 画面から見せる場所（設定画面に「ライセンス」項目を設けるか）。

## 3. VC++ ランタイムの再頒布

### 3.1 現状

- `scripts/local-llm/place-bundle.mjs` が、`C:/Program Files (x86)/Microsoft Visual Studio/2022/BuildTools/VC/Redist/MSVC/14.44.35112/x64/Microsoft.VC143.CRT` から次の DLL を llama-server の隣にコピーしている（app-local 方式）。

- 同梱物の README.txt には、「Distributable Code として再頒布」と記載している。

### 3.2 Microsoft の条件

**再頒布リスト（REDIST.txt に当たるもの）**

- 出典: https://learn.microsoft.com/en-us/visualstudio/releases/2022/redistribution
- 有効なライセンスを持つ Visual Studio の利用者は、`VC\redist` 配下のファイル（サブフォルダを含む）を、**改変せずに**自分のプログラムと一緒に配ってよい。
- `debug_nonredist`（デバッグ用 DLL）は配れない。
- したがって、現在コピーしている CRT DLL は**リストの対象内**。

**ライセンス本文の「Distributable Code」条項**

- 出典: https://visualstudio.microsoft.com/license-terms/
- ページがスクリプトで描画されるため、本文を取得できなかった。二次資料から読み取った骨子は次のとおり。
  - 配れるのはオブジェクトコードだけ。
  - アプリ側に主要な機能（significant primary functionality）があること。
  - 配布先に、同等以上に保護的な条件に同意させること。
  - Microsoft の商標を使わないこと。
  - 著作権表示を変えないこと。
  - 除外ライセンス（コピーレフト系）の対象にしないこと。
  - Microsoft への補償（indemnify）。
- 参考: https://learn.microsoft.com/en-us/answers/questions/661883/
- **原文は、インストール済みの VS／Build Tools の License Terms で人が確認する必要がある。**

**Build Tools だけで使う場合**

- 出典: https://devblogs.microsoft.com/cppblog/updates-to-visual-studio-build-tools-license-for-c-and-cpp-open-source-projects/ （2022-08）
- ライセンスなしで使ってよいのは、オープンソースの C++ 依存物をソースからビルドする場合に限られる。
- 独自（proprietary）のコードには VS ライセンスが要る。
- 再頒布リストも「ライセンスを持つ VS 利用者」を前提にしている。
- このため、Build Tools の Redist フォルダから DLL を再頒布する権利は、**チームが有効な VS ライセンスを持っていることが前提**と読むのが安全。
  - Community 版にも利用条件がある（個人、OSS、学習用途、小規模組織など）。

**Microsoft の推奨**

- 出典: https://learn.microsoft.com/en-us/cpp/windows/redistributing-visual-cpp-files 、 https://learn.microsoft.com/en-us/cpp/windows/deployment-in-visual-cpp
- 推奨は、vc_redist でシステムに一括導入する方式（central deployment）。Windows Update が更新してくれる。
- app-local 方式は、Microsoft が自動更新できないため非推奨。採用するなら、アプリ側で更新を配る責任がある。
- 静的リンクも、更新のたびに再ビルドが要るため推奨はされていない。
- マージモジュール（.msm）は非推奨。

**vc_redist の固定ダウンロード URL**

- x64 用: https://aka.ms/vc14/vc_redist.x64.exe
- vc_redist 自体のライセンス: https://aka.ms/VCRedistLicense
- 出典: https://learn.microsoft.com/en-us/cpp/windows/latest-supported-vc-redist

### 3.3 選択肢（Tauri の NSIS・MSI インストーラ）

| 案 | やり方 | 長所 | 短所・条件 |
|---|---|---|---|
| ① 現状維持（app-local） | 今のまま DLL を `local_llm/runtime/` に同梱 | オフラインで入る。管理者権限が要らない。仕組みが単純 | VS ライセンスが前提。CRT のセキュリティ更新は、アプリの更新で自分たちが配る必要がある。Microsoft は非推奨 |
