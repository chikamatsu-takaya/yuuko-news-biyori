# フロントエンド詳細ルール（React / TypeScript）

共通ルールは `AGENTS.md` を正とする。本ファイルはフロント領域を扱うときだけ読む。

## 責務分離（React / TypeScript 側に持たせるもの）

- 画面（メイン / ニュース閲覧 / 設定 / ゆうこ辞書 / ニュース履歴 / カスタマイズ / ガチャ）
- ゆうこの表示・画面端からの登場演出・吹き出し・軽量プレビュー・ランクアップ通知モーダル
- 画面レイアウト・画面遷移・テーマ反映・ユーザー操作受付
- Tauri command 呼び出し

React は「何を表示するか」を扱う。複雑な判定・状態変更・中核処理は Rust 側の Tauri command に委ね、React に持ちすぎない。RSS取得・AI API呼び出し・ファイル保存を React に書かない。API キー・秘密情報を React に持たせない。

## React ⇄ Rust 接続

- Rust から受け取るデータは、UI 表示に適した DTO / 型として整形済みの前提で扱う。
- Tauri command 呼び出し名は Rust 側の定義と一致させる。
- UI 都合の一時状態と、アプリ永続状態を混同しない。

## UI / UX 原則

- 通常時はバックグラウンド待機。ユーザーが望まない限りメイン画面を常時表示しない。画面は必要時のみ表示。
- 通知は可愛いが邪魔しない。アニメーションは軽量。派手さより快適さ。
- ゆうこはキャラクター体験の中心。登場・吹き出し・再説明・報酬通知は重要要素だが「軽く・自然に・邪魔しない」を優先。非表示時に高負荷で動き続けない。ゆうこ登場・通知挙動の詳細設計書（`docs/02_design/ゆうこ登場・通知挙動_詳細設計書.md`）に反しない。
- ソフト内では原文の大量表示を避け、再説明文・要点整理・注目ポイント・用語補足・ゆうこの意見を主軸にする。原文確認は出典リンクへ誘導し、リンクはユーザー操作を挟んで開く。AI出力内のURLを自動リンク化しない。

## React UI 実装方針

- 画面単位でコンポーネントを分ける。共通UI部品は `components/`、モーダル/ポップアップは `dialogs/`、Tauri command 呼び出しは `services/`、型は `types/` に整理する。
- 1コンポーネントに過剰な責務を持たせない。

## 命名

- Reactコンポーネント / ファイル: `PascalCase`（例 `NewsCard.tsx` / `SettingsScreen.tsx`）。画面は `XxxScreen`、モーダルは `XxxDialog` / `XxxModal`。
- hooks: `useXxx`（camelCase）。型 / interface: `PascalCase`。関数・変数: `camelCase`。
- Tauri command ラッパー: 必要に応じ `xxxApi.ts`。既存命名と衝突する場合は既存を優先し、同義概念に別名を増やさない。

## 性能（フロント）

- バックグラウンド時に不要な描画をしない。不要なタイマー / ループ / 常時ポーリングを増やさない。
- 再レンダリングが過剰にならないようにする。重い・無限ループアニメーションを避ける。大きなデータを毎回再構築しない。

## エラー処理・フォールバック（フロント）

- 失敗時は安全側へ。Tauri command 失敗時は React をクラッシュさせずエラー表示する。ユーザー向け文言は過剰な不安を与えない。
- 用語解説失敗時は再選択を促す補助メッセージ。AI要約失敗時も記事情報は表示可能に。

## 変更後の確認

- `pnpm build` / `pnpm lint` / `pnpm run typecheck`（`tsc --noEmit`）
- UI変更時は Playwright（`pnpm exec playwright test`、必要なら `-g "<keyword>"`）。
- 実行できない場合は未実行と理由を報告する。
- 表示崩れ・主要画面サイズでの破綻・アニメーション負荷・メイン画面非表示前提・ゆうこ表示の邪魔・Rust責務の混入がないかを確認する。
